# 部署

服务器：`bugu.char46.top`（在 Cloudflare 后面）

> **已经部署好了**（2026-08-27）。下面是当时实际做的事，
> 重装或者换机器时照着走。

## 这台机器的实际情况

| 项 | 是什么 |
|---|---|
| 系统 | Debian 13 (trixie) x86_64 |
| 反代 | **Caddy** v2.11（不是 nginx）—— 自动签证书，不用 certbot |
| Node | v22.21.1，装在 `/root/.local/share/pnpm/` 下 |
| 同机还跑着 | headscale、frps、easytier、rustdesk、mosquitto、gohttpserver…… |

**最后一条最要紧：这台机器不只有我们。** 所有改动都必须是只增不改的，
碰 Caddyfile 之前先备份、`caddy validate` 过了再 reload。

## 踩到的两个坑

**一、node 在 `/root/.local` 下，服务进不去。**
服务以 `bugu` 用户跑，`/root` 是 700，而且单元里还开着 `ProtectHome=true`。
解法是把 node 二进制复制一份到 `/opt/bugu-stats/bin/`（118 MB）——
自带一份还有个好处：以后作者升级他自己的 node，不会把这个服务带崩。

**二、`MemoryDenyWriteExecute=true` 会让 Node 启动即崩。**
V8 要 JIT，必须能把内存页改成可执行，这条 systemd 加固跟它天生冲突。
崩溃栈里是 `v8::base::OS::SetPermissions`。别的加固项都留着，只关这一条。

## 一、装


```bash
# Node 22+（node:sqlite 要它）
node -v

sudo useradd -r -s /usr/sbin/nologin bugu
sudo mkdir -p /opt/bugu-stats /var/lib/bugu-stats
sudo chown bugu:bugu /var/lib/bugu-stats
```

把本地 `pnpm build` 出来的 `dist/`、`package.json`、`node_modules/`
传到 `/opt/bugu-stats/`（只有一个依赖 `jose`）。

```bash
sudo cp deploy/bugu-stats.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now bugu-stats
curl -s localhost:8787/healthz     # {"ok":true}
```

## 二、反代

这台机器用的是 **Caddy**，证书它自己签，不用 certbot。

```bash
# 先备份！这个 Caddyfile 管着这台机器上所有的站
cp /etc/caddy/Caddyfile /etc/caddy/Caddyfile.bak-$(date +%F-%H%M%S)
cat deploy/Caddyfile.片段 >> /etc/caddy/Caddyfile
caddy validate --config /etc/caddy/Caddyfile --adapter caddyfile   # 必须先过这一关
systemctl reload caddy
```

**Cloudflare 的 SSL 模式要选 Full (strict)。** 选 Flexible 的话
CF 到源站那一段是明文的，等于白配证书。

## 三、验

```bash
curl https://bugu.char46.top/healthz
curl -i https://bugu.char46.top/api/v1/u/nobody/stats     # 404，正常
```

## 四、备份

整个库就是一个文件：

```bash
sqlite3 /var/lib/bugu-stats/stats.db ".backup /var/backups/bugu-$(date +%F).db"
```

## 之后才做：API 资源

**顺序不能反。** 先确认上面都通了，再去 Logto：

1. 建 API 资源，标识符 `https://api.ferret.icu/bugu`，权限 `stats:write`
2. 授权给「不咕」这个应用
3. `BUGU_AUDIENCE=https://api.ferret.icu/bugu`，重启服务
4. 客户端那边把 `resource` 填回去，重新打包

先填资源标识符会怎样：Logto 那边资源不存在 → `invalid_scope` →
**整个登录都进不去**。已经踩过一次了。
