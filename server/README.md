# 不咕鸟 · 对外统计服务

**只吐七个数，不碰一个字正文。**

别的网站想显示「某某今天写了多少字、连胜多少天」，读这个：

```
GET https://bugu.char46.top/api/v1/u/<短名>/stats
```

## 为什么需要它

登录那一块是 Logto 管的，但 **Logto 不存字数**。它只知道你是谁，
不知道你今天写了几个字。所以要有这么一台小服务：

```
不咕鸟客户端 ──带 Logto 令牌──► PUT /api/v1/me/stats ──► SQLite
                                                          │
别人的网站 ◄── GET /api/v1/u/<短名>/stats（公开、无需令牌）◄┘
```

## 接口

| 方法 | 路径 | 要令牌 | 干什么 |
|---|---|---|---|
| GET | `/healthz` | 否 | 活着没有 |
| GET | `/api/v1/u/:handle/stats` | 否 | **公开只读**，开 CORS |
| GET | `/api/v1/me` | 是 | 我是谁、短名是什么 |
| PUT | `/api/v1/me/handle` | 是 | 认领/改短名 |
| PUT | `/api/v1/me/stats` | 是 | 推那七个数 |
| DELETE | `/api/v1/me` | 是 | 把我的数据整个删掉 |

公开接口吐出来长这样：

```json
{
  "handle": "mingting",
  "updatedAt": "2026-08-27T10:00:00.000Z",
  "date": "2026-08-27",
  "todayWords": 1234,
  "weekWords": 5678,
  "streak": 9,
  "bestStreak": 40,
  "dailyFloor": 2000,
  "daysTogether": 100
}
```

**没有别的。** 没有书名、没有章节名、没有正文、没有邮箱，
连 Logto 那边的用户号（`sub`）都不吐 —— 那玩意儿漏出去，
等于把这个人在不同网站上的身份对上号。

## 两条不许破的规矩

**一、只有那七个数能出去。**
客户端那边有一道挑选，但服务端不能指望它 —— 改过的客户端、
手写的 curl、版本不匹配，都可能往上塞东西。所以这边
**显式挑七个字段**，别的一律丢掉，数据库里也没有别的列。

**二、令牌必须真验。**
绝不能「解开 JWT 看看 sub 就算了」。不验签的 JWT 谁都能伪造成
别人的 `sub`，然后以别人的身份改他的数据 —— 而接口看起来一切正常。
这一条错了完全看不出来，所以测试里专门有一条伪造令牌的用例。

## 认两种令牌

Logto 发什么令牌，取决于客户端要没要 API 资源：

- **要了** → JWT，本地拿 JWKS 验签，快
- **没要** → 不透明令牌，拿去问 Logto 的 userinfo

现在客户端还没要（建了 API 资源但服务没跑起来会把登录整个搞挂，
已经踩过一次），所以**走的是第二条**。两种都支持，以后切过去不用改代码。

## 跑起来

```bash
pnpm install
pnpm test          # 36 个测试
pnpm build
BUGU_DB=./dev.db pnpm start
```

部署见 `deploy/部署.md`。

## 技术选择

- **`node:http`，没有框架** —— 五条路由用不着，少一层依赖就少一层
  要跟着升级的东西。这服务的价值在于十年后还能跑
- **`node:sqlite`（Node 22 内置）** —— 一人一行七个整数，
  为这点数据装 Postgres 不划算；整个库是一个文件，备份 = 复制
- **`jose`** —— 唯一的依赖。验签是安全要害，不自己手写
