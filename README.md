# 不咕鸟

**不咕** 一个给中文长篇作者用的写作软件。

 - 类多邻国的连胜机制。
 - 可选择自己的打卡标准，只有周末写、每天写2000，都可以持续打卡。
 - 稿子存在本地，不上传云端。随时无痛卸载。

**轻AI功能** 
 - 接入API后，可一键充能、润色、续写。
 - 所有AI功能仅提供简单帮助，你的作品仍然你说的算。

## 下载

去 [Releases](../../releases) 拿最新的 `buguniao-x.y.z-win-x64.exe`，双击就跑，
不写注册表、不留安装记录，放 U 盘也行。同一个 Release 里的 `SHA256SUMS.txt` 可以对校验值。

 - Windows 桌面端，免安装。目前是测试版，作者本人在日常使用。
 - **Windows 会拦一下。** 这个包没有代码签名证书，会弹「已保护你的电脑」。点「更多信息」→「仍要运行」。
 - 不放心就先对一下校验值。没办法，证书一年要几千块。

每一版改了什么见 [更新日志](更新日志.md)。

## 它解决什么

| 长篇写作特有的麻烦 | 不咕鸟的答案 |
|---|---|
| 写到八十万字，忘了第十二章埋的那块玉佩 | 伏笔追踪：埋在哪、该在哪收、过期没收会标红 |
| 设定集查一次要跳出去一次，回来就断了思路 | 便利贴浮出：把设定卡拖到稿纸上，它就浮在那儿 |
| 改错了想回去，可上一版已经没了 | 版本历史：每次保存留一份，随时翻回去 |
| 写不下去，开始咕 | 每日目标、连胜、请假、番茄钟、年度热力图 |
| 分支剧情写着写着自己都绕不清 | 分支节点图 + 体检：断头路、孤儿、死路、走不到的分支 |

还有：全文检索（中文分词，几十万字秒回）、双链 `[[ ]]`、
剧本排版、导出 Ren'Py / ink 骨架、Word / txt 导出、Scrivener 导入、
接 AI（DeepSeek / Gemini / 智谱等，**你不点它就不动**）。

## 四条不肯让步的规矩

这四条是整个软件的地基，任何功能都不许绕过它们。

1. **文件即真相。** 正文是纯 Markdown，目录就是文件夹。
   索引、缓存、统计全都可以删掉重建；**正文不能**。
2. **不发明只有本软件认得的东西。** 便利贴用 `@`、伏笔用 HTML 注释、
   链接用 `[[ ]]`、游戏节点用 `#` —— 都是别的编辑器打开也不至于看不懂的写法。
3. **不上传正文。** 一个字都不传。
   [对外统计](更新文档/08-账号与对外接口.md)只发七个整数（连胜、字数、目标），
   而且要你先登录、先认领短名、先自己打开开关，三样齐了才发。
4. **AI 永远不会自己跑。** 不自动续写、不后台调用、不偷偷花钱。

## 自己跑起来

需要 Node 22+ 和 pnpm。

```bash
cd app && pnpm install
```

```bash
cd app/packages/desktop && pnpm dev
```

其它常用命令：

```bash
cd app && pnpm check
```

```bash
cd app/packages/desktop && pnpm smoke
```

`pnpm check` 是类型检查 + 全部单元测试；`pnpm smoke` 会**真的启动一个窗口**，
从渲染进程里把 `window.bugu` 的方法依次走一遍完整写作流程 ——
单元测试测得到纯逻辑，测不到「IPC 有没有对上、React 白没白屏」。

`pnpm dist` 出免安装包，产物在 `packages/desktop/release/`。

## 仓库长什么样

```
app/
  packages/
    core/       两端共享的纯逻辑。不许出现 fs / window / Electron
    desktop/    Electron：main（磁盘、网络、密钥）/ preload / renderer
    ui/  mobile/
server/         对外统计服务。五个接口，node:http + node:sqlite，没有框架
更新文档/        设计文档。改代码之前先读这里
开发记录.md      踩过的坑，一条一条记着为什么这么做
更新日志.md      每一版改了什么
```

**`core` 是纯函数库**，所以它好测、两端能复用。
平台相关的东西（文件读写、加密存储、网络）全在 `desktop` 里。

写代码之前建议先读 [更新文档/03-数据格式规范](更新文档/03-数据格式规范.md) ——
它是全项目的地基，别的都建在它上面。

## 报 bug

开 [Issue](../../issues)，麻烦带上三样：

1. **版本号**（设置 → 账号最底下那行）
2. **哪一步做了什么**，越具体越好
3. 显示问题的话，**截个图**

最想让人帮忙盯的是 **有没有丢过字**。那是这个软件唯一不能出的错。
要是遇到「刚打的字没了」，请立刻告诉我，别管别的。

> 说清楚「为什么难受」比说清楚「哪儿坏了」更有用。
> 0.3 里的合并写法 `<- 甲、乙` 就是从一句
> 「有分歧但之后故事线依旧一样的分支设置十分麻烦」长出来的。
> 见[致谢](更新日志.md#致谢)。
