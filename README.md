# 不咕鸟

**不鸽，不断更。** 一个给中文长篇作者用的写作软件。Windows，免费，开源。

---

仔细想来，从小学四年级开始在本子上写第一篇故事，写小说的勾当已经做了十多年了。
期间我换了很多写作软件，但要么功能太多，写十分钟文，五分钟在淘宝；
要么功能太少，连排版都要手动一个个调。一直以来，我都想搞一个自己的写作软件。
好在进入了 AI 时代，作为作者的职业生命被取代，却也给了这个软件问世的机会。

我管它叫不咕鸟，布谷鸟常出现在时钟里，本就有准时的意思，不咕这个谐音，
我认为是很妙的。这是对我自己的期待，希望自己可以日日更 ——
可能就是所谓的差生文具多，我其实一直有拖更的毛病。

于是乎，这一款软件就这样出现了。目前已经走过了 5 个测试版本，
0.1 的全新出炉，0.2 的 bug 修复，0.3 的外观调整，0.4 的功能追加，
以及 0.5 实装了双屏参考编辑。各位可能能从各个版本的名字中看出，
这些都是化用自《最终幻想 14》的版本名。但接下来不会有 0.6 和 0.7 了，
因为我讨厌虚无主义。

愿意使用我软件的朋友，非常感谢。我不会编程也不会设计界面，
勉强靠着人工智能辅助，制作出这么一款软件来。如果说这玩意有什么可取之处，
这里的每一个功能都是我觉得需要的，每一次 UI 迭代都是朝着我觉得更舒服的方向制作，
每一项设计都是我作为一个作者的经验之谈。这软件并非我一力开发，
但我忠实地为每一次共鸣感到欣喜。

看到这里的朋友们，愿我们可以一同共享文字的美妙。

> 下方功能文档，由 Claude 编辑。

写长篇的人有两种怕：**怕忘，怕咕。**

怕忘 —— 写到八十万字，第十二章埋的那块玉佩早就想不起来了，
配角的眼睛颜色前后不一样，自己都不敢往回翻。
怕咕 —— 今天不想写，明天也不想写，一个月之后这本书就废在那儿了。

不咕鸟只做这两件事。它不想成为你的第二个大脑，
也不打算教你怎么写小说 —— 它管的是「别忘」和「别停」。

> 目前是测试版，作者本人每天在用它写自己的稿子。

---

## 稿子是你的

**正文就是你自己文件夹里的 `.md` 文件**，目录就是文件夹，
用记事本能打开、能读、能改。不咕鸟的索引、统计、缓存全都可以删掉重建，
**唯独正文不能** —— 所以软件坏了、卸载了、你不想用了，
稿子都还在，一个字不少。

**正文一个字都不上传。** 没有云端，没有「同步中」，
不登录也一个功能都不少。

---

## 怕忘：那块玉佩埋在第十二章

- **伏笔追踪** —— 埋在哪、该在哪收、过期没收会标红。也能先记下「我要埋一个」，回头再写。
- **便利贴** —— 把设定卡拖到稿纸上，它就浮在那儿。查一次设定不用跳出去一次，回来还接得上刚才那句。
- **双屏对照** —— 左右两块稿纸。可以是另一章，也可以是**同一章的另一处**：两边是同一份文档的两个视图，对着开头改结尾，**滚动绝不同步**（这件事 Typora 做不到，Scrivener 要把一章拆成两个文件）。
- **全文检索**（中文分词，几十万字秒回）、双链 `[[ ]]`、**版本历史**（每次保存留一份，随时翻回去）。

---

## 怕咕：今天不想写

- **两条目标线**：底线和理想线，工作日休息日分开，每个数都能改。
- **请假日** —— 请了假不算达标，但**连胜不断**。生活里本来就有写不了的日子，为这个把三十天连胜清零，只会让人干脆不写了。
- **改了目标，以前的日子仍按当时的目标判**。不许用今天的标准回头否定过去的自己。
- 连胜徽章、番茄钟、年度热力图、这一坐写了多少 / 删了多少 / 净产出多少。

---

## 如果你写的不是小说

- **剧本**：认得出场景、动作、台词，从设定集认角色名并单独排行；谁的戏多、谁好久没出声了、场次重排。
- **游戏剧本**：分支节点图画出来，**体检**替你抓断头路、孤儿节点、死路、走不到的分支、写坏的条件；能从任意节点试玩，能导出 Ren'Py / ink 骨架。

新建作品时选一种，选错了回书架右键能改。

---

## 它不做的事

- **AI 不会私自改你的东西。** 它写的一律先落在草稿里，你点头才进稿子；正文、大纲、设定集里已有的文件它一个字都不碰。花多少钱看得见，接哪家、单价多少都是你自己填。本体里它还是**你不点就一动不动**。
- **不发明只有本软件认得的写法。** 便利贴用 `@`、伏笔用 HTML 注释、链接用 `[[ ]]`、游戏节点用 `#`，别的编辑器打开也不至于看不懂。
- **不替你改稿。** 检查类的功能只标出来，判断是你的事。
- **不闭源。** GPL-3.0，随便用、随便改、随便传。

更多功能见 [更新日志](更新日志.md)；软件里按 **F1** 有图文教程，
书架和三种稿纸各一份。

## 下载

去 [Releases](../../releases) 拿最新的那一版，两种装法挑一个：

| 拿哪个 | 是什么 |
|---|---|
| **`buguniao-setup-x.y.z.exe`** | **安装版。装新版会自动把旧版卸掉**，你机器上永远只有最新那份。不要管理员权限，装在自己的用户目录下。 |
| `buguniao-x.y.z-win-x64.exe` | 免安装版。双击就跑，不写注册表、不留安装记录，放 U 盘也行。换版本得你自己记着删掉上一个 exe。 |

两种装法**共用同一份配置**（`%APPDATA%\不咕鸟`），来回换不丢设置、不丢连胜。
卸载不删配置，更不碰你的稿子 —— 稿子从来就只在你自己选的那个文件夹里。
同一个 Release 里的 `SHA256SUMS.txt` 可以对校验值。

> 文件名是英文的：GitHub 会把附件名里的中文全替换掉，中文名传上去会变成 `_.v0.3.exe`。
> 下下来自己改名就行。

> **Windows 会拦一下。** 这个包没有代码签名证书（一张要几千块一年），
> 所以 SmartScreen 会弹「已保护你的电脑」。点「更多信息」→「仍要运行」。
> 不放心就先对一下校验值。

每一版改了什么见 [更新日志](更新日志.md)。

## 它不适合谁

说在前面，省得你下下来才发现：

- **只有 Windows。** 没有 Mac、没有 Linux 版。手机端在做，但定位是**只增不改** —— 随手记一条灵感可以，改正文不行（这样两台设备永远不会写同一个文件，冲突在物理上不会发生）。
- **不是多人协作工具。** 一本书一个作者，没有共同编辑、没有评论区。
- **没有云。** 换台电脑接着写，靠的是你把工作目录放在坚果云 / OneDrive 这类同步盘里 —— 软件认得出「这一篇在别处也改过」，但同步本身不归它管。
- **不管排版。** 它是写稿子的地方，不是排版软件。要交付 Word 就导出，剩下的事交给 Word。
- **还在测试版。** 功能会变，界面会变。稿子不会 —— 它一直是那些 `.md` 文件。

---

## 四条不肯让步的规矩

上面那几条「不做的事」，说到底都是从这四条推出来的。
它们是整个软件的地基，任何功能都不许绕过。

1. **文件即真相。** 正文是纯 Markdown，目录就是文件夹。
   索引、缓存、统计全都可以删掉重建；**正文不能**。
2. **不发明只有本软件认得的东西。** 便利贴用 `@`、伏笔用 HTML 注释、
   链接用 `[[ ]]`、游戏节点用 `#` —— 都是别的编辑器打开也不至于看不懂的写法。
3. **不上传正文。** 一个字都不传。
   [对外统计](更新文档/08-账号与对外接口.md)只发七个整数（连胜、字数、目标），
   而且要你先登录、先认领短名、先自己打开开关，三样齐了才发。
4. **AI 不会私自改你的东西。** 它的产出一律先进草稿，采纳是你按的；
   已经写下的字它碰不着。花了多少钱一笔笔记着。

## 自己跑起来

需要 Node 22+ 和 pnpm。

```bash
cd app && pnpm install
```

```bash
cd app/packages/desktop && pnpm dev
```

其它常用命令：

```bash
cd app && pnpm check
```

```bash
cd app/packages/desktop && pnpm smoke
```

`pnpm check` 是类型检查 + 全部单元测试；`pnpm smoke` 会**真的启动一个窗口**，
从渲染进程里把 `window.bugu` 的方法依次走一遍完整写作流程 ——
单元测试测得到纯逻辑，测不到「IPC 有没有对上、React 白没白屏」。

`pnpm dist` 出两个包（安装版 + 免安装版），产物在 `packages/desktop/release/`。

要发版用 **`pnpm release`**：打完包之后它会把**旧版本的 exe 收进
`release/历史版本/`**，根目录下永远只摆当前这一版，再给当前版本算一份
`SHA256SUMS.txt`。旧包一个都不删 —— 没有代码签名证书的软件只能靠校验值自证，
而校验值要有意义，被校验的那个文件得一直在作者手上。

## 仓库长什么样

```
app/
  packages/
    core/       两端共享的纯逻辑。不许出现 fs / window / Electron
    desktop/    Electron：main（磁盘、网络、密钥）/ preload / renderer
    ui/  mobile/
server/         对外统计服务。五个接口，node:http + node:sqlite，没有框架
更新文档/        设计文档。改代码之前先读这里
开发记录.md      踩过的坑，一条一条记着为什么这么做
更新日志.md      每一版改了什么
```

**`core` 是纯函数库**，所以它好测、两端能复用。
平台相关的东西（文件读写、加密存储、网络）全在 `desktop` 里。

写代码之前建议先读 [更新文档/03-数据格式规范](更新文档/03-数据格式规范.md) ——
它是全项目的地基，别的都建在它上面。

## 报 bug

开 [Issue](../../issues)，麻烦带上三样：

1. **版本号**（设置 → 账号最底下那行）
2. **哪一步做了什么**，越具体越好
3. 显示问题的话，**截个图**

最想让人帮忙盯的是 **有没有丢过字**。那是这个软件唯一不能出的错。
要是遇到「刚打的字没了」，请立刻告诉我，别管别的。

> 说清楚「为什么难受」比说清楚「哪儿坏了」更有用。
> 0.3 里的合并写法 `<- 甲、乙` 就是从一句
> 「有分歧但之后故事线依旧一样的分支设置十分麻烦」长出来的。
> 见[致谢](更新日志.md#致谢)。
