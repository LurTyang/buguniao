## 1. 修 bug：拖便利贴会往正文里插人名

> 作者原话：「便利贴应该可以自由拖动，不会吸附；不应该有人名被拖出来。」

**这不是功能，是 bug。** 成因已经查清：

```
DirectoryTree.tsx:261 / 281
  e.dataTransfer.setData('application/x-bugu-sticky', card.path)
  e.dataTransfer.setData('text/plain', card.title)   ← 祸根
```

CodeMirror 认 `text/plain` 的拖放，于是**把卡片标题当正文插进去了**。
而 `placeNewSticky()` 把便利贴摆在落点，正好压在那个刚被插进来的名字旁边——
所以「卡在人名旁边」不是吸附，是两个东西掉在同一个点上。
`StickyLayer.tsx` 里**没有任何吸附代码**，本来就是自由拖动。

### 怎么修

1. **拖便利贴时不要再放 `text/plain`。** 自定义类型 `application/x-bugu-sticky`
   已经足够让拖放启动，`text/plain` 纯属多余。
2. **编辑器上再挡一道**：`dragover` / `drop` 时如果
   `types.includes('application/x-bugu-sticky')` 就 `preventDefault()`，
   保证 CodeMirror 永远碰不到这个拖放。

两道都要。只做第一道的话，哪天有人为了别的目的又把 `text/plain` 加回来，
正文里就会重新开始冒出人名——而**这种 bug 不会报错，只会悄悄改你的稿子**。

### 要钉住的测试

- 拖一张卡到稿纸上，**正文一个字都不许变**（拿保存前后的 body 比）
- 便利贴落在鼠标松开的地方，且之后能自由拖走
- 已经贴过的卡再拖一次是**挪位置**，不是贴第二张

> 顺带记一条教训：`setData('text/plain', …)` 是「顺手为了兼容性加的」，
> 加的时候没人想到稿纸里坐着一个会接管拖放的编辑器。
> **凡是往全局通道里塞东西，都要问一句「谁还会听见」。**

## 2. 奖状 【M】

按作者的定义重做——**跟上一稿完全不是一个东西**：

> 成就在服务器，开发者手动给予。用于纪念一些比赛等等，
> **并不会自动获得，并不是传统的里程碑。**

所以：**没有清单、没有条件、没有自动判定。** 上一稿那 19 条全部作废。
它是**奖状**，不是成就系统——文档里也统一改叫奖状，免得又被人当成里程碑去实现。

- 显示在**用户名与「一起写了 XX 天」之间**
- 2–6 个字，楷体
- **吃掉现在的连胜徽章**（`badgeFor()`）——一个位置不放两套荣誉
- **只有本人看得见**（作者定：不进公开接口）
- 有多个的话**在客户端里切换挂哪一个**，挂哪个存在本机设置里

### 服务器这边

新一张表，跟那七个数分开：

```sql
CREATE TABLE awards (
  sub   TEXT NOT NULL,           -- 谁的
  id    TEXT NOT NULL,           -- 稳定标识，比如 nano-2026
  name  TEXT NOT NULL,           -- 显示出来的 2–6 个字
  note  TEXT NOT NULL DEFAULT '',-- 说明，比如「2026 年不咕鸟征文 一等奖」
  at    TEXT NOT NULL,           -- 什么时候发的
  PRIMARY KEY (sub, id)
)
```

**奖名直接存**，不存在一份「奖项清单」里——奖是一次性的，
为一次征文去改代码再部署，这功能就没法用了。

接口：

| 方法 | 路径 | 谁能用 |
|---|---|---|
| GET | `/api/v1/me` | 本人（返回里加 `awards`） |
| PUT | `/api/v1/admin/awards` | 颁奖的人 |
| DELETE | `/api/v1/admin/awards` | 颁奖的人 |

**`/api/v1/u/<handle>/stats` 不动**——奖状不进公开接口，
那七个数还是那七个数。

### 关于「管理员账户」

> 作者原话：「是否代表需要有管理员账户这种东西存在？我不太希望这玩意存在。」

**不需要，而且确实不该有。** 说清楚这件事：

服务器上只多一个环境变量 `BUGU_ADMIN_SUBS`，里面写作者**已有账号**的
Logto `sub`。判定就一句 `admins.has(sub)`。

- 没有新账号类型、没有新密码、没有新登录方式
- 没有「管理员」这个身份概念——只有一张 systemd 配置里的名单
- 名单在**服务器的配置里**，不在数据库里、不在客户端里，
  改它要能登上那台机器

**真正要避免的是另一件事：别把颁奖界面打进写作软件。**
不咕鸟是 GPL 开源的，藏一个「只有管理员看得见」的面板等于把它写进每个人的包里——
虽然服务器那关照样过不了，但这是白白多出来的一片攻击面和一堆解释成本。

所以：**写作软件里一行颁奖代码都没有。** 发奖是服务端那张名单的事，
跟每个人手上这个包无关。

### 客户端显示

- 从 `/api/v1/me` 拿，**在本地缓存一份**——离线时奖状不该消失
- 鼠标停上去显示 `note`
- 有多个时在设置里选挂哪一个（选择存本机）
- 客户端**只读**：拿到什么显示什么，不判定、不发、不改

## 3. 外观

### 3.1 两处都能改 【S】

> 作者原话：「外观在稿纸设置中，将它复制一份在书架页的设置中，两个地方都能改。」

书架页的设置弹窗现在只有：账号 / 码字计划 / AI / 作品库。
加一个**外观**，跟稿纸侧边栏那份是**同一个组件、同一份配置**。

不是复制粘贴两份代码——那样改一处忘一处，两边就会不一样。
`SettingsPanel` 里外观那一节抽成 `AppearancePanel`，两处都用它。

### 3.2 默认主题砍到三个 【S】

> 「默认主题保留三个就好，大多让用户自定吧。」

从五档砍成三档：

| 留 | 砍 |
|---|---|
| **纸白**（原版，默认） | ~~纸黄~~ |
| **护眼**（豆沙绿） | ~~墨灰~~ |
| **夜间**（近黑） | |

砍掉的两档不删代码、挪进「更多」里？——**不。直接删。**
留一个半藏起来的选项，等于既没减少选择困难，又多一份要维护的配色。
想要旧纸色的人，用下面的自选 CSS 就能做到，而且能做得更合他意。

配套是把**自定义那条路修宽**（§3.3、§3.4），不然砍了就是纯损失。

### 3.3 主题的补充 【S】——全部采纳

- **换主题时给一张即时预览**，不用切回稿纸看
- **Typora 主题装不上时说人话**：现在读不到就静默当没配。要分清楚是
  文件没了、还是里面根本没有 `#write`
- **每个主题各自记住字号**：夜间想大一号，是常见需求

### 3.4 导入字体 【M】

> 「可做一个导入字体功能，让用户自己导入。」

挑一个 `.ttf` / `.otf` / `.woff2`，复制进 `userData/fonts/`，
注册成 `@font-face`，然后它就出现在字体下拉里，跟内置的那几款并列。

几条要想清楚的：

- **复制进来，不是记路径。** 记路径的话，他哪天清理下载文件夹，字体就没了
- 大字体（中文字库动辄十几 MB）要给个进度，别让界面像卡死
- **不做字体分发**：只用他自己机器上的字体文件。版权是他的事，我们不掺和
- 导入失败（不是字体、坏文件）要说清楚，别只说「失败」

## 4. 写作体验

### 4.1 打字机模式 【M】——横向、竖向各一个开关

> 「设置横向、竖向两个打字机模式，分别开关，在稿纸设置内。」

作者的定义：

> 「普通的打字机是行始终在中间，横向打字机就是**列始终在中间，稿纸也会横着动**。」

- **竖向打字机**：当前**行**永远停在屏幕的固定高度（默认中部），
  往下写时是纸在往上走、眼睛不动。CodeMirror 给足 `scrollMargin` 就能做
- **横向打字机**：当前**列**（也就是光标）永远停在水平中央，
  打字时纸往左走、光标不动

两个**分别开关**，都放在稿纸的外观设置里。默认都关。

⚠️ **横向那个有个前提：稿纸现在是自动折行的。**
折行的时候一行永远填不满、光标也就永远走不到右边，横向根本没得动。
所以开横向打字机时要**同时关掉自动折行**，让一行一直往右延伸。

这件事得让作者知道，不能默默改掉他的排版——所以那个开关下面写一句
「打开它会关掉自动折行」，而不是等他发现稿纸忽然能左右拖了。

（如果你其实想要的是**竖排书写**——从右往左、像古籍那样——那是另一件事，
CSS 的 `writing-mode` 能做，但整个稿纸、便利贴、光标计算都要跟着改，
不是 0.4 的量级。说一声我单独排。）

### 4.2 智能替换 【M】

> 「三个在设置中合并一个智能替换标签页，并且可以添加其他的标签转化。」

设置里单开一个**智能替换**页，是一张**规则表**，不是三个写死的开关。

内置这几条（都能单独关）：

| 打的 | 变成 | 默认 |
|---|---|---|
| `"` `'` | **中文弯引号 “ ” ‘ ’** | **开** |
| `"` `'` | 直角引号 「」『』 | 关（跟上一条二选一） |
| `--` | `——`（两个字宽） | 开 |
| `...` | `……` | 开 |

> **默认是弯引号，不是直角引号。** 作者的原话：「中文引号使用频率实则
> 远高于直角引号」。上一稿我默认给了直角引号，是照搬了轻小说的排版习惯——
> 那不是大多数人写东西的样子。直角引号留作可切换的一档。

下面是**自定义规则**：他自己加「打什么 → 变什么」，一行一条，能删能停用。

三条不许破的：

1. **只在输入的那一刻替换，绝不动文件里已有的字。** 不做全文扫描式的「修正」
2. **撤销一次就退回你原本打的那个字符。** 自动替换而 Ctrl+Z 退不回去，
   会让人不敢打字——这一条比功能本身还重要
3. **一键全关。** 页面顶上一个总开关

### 4.3 专注模式 【S】

当前段落之外的文字变淡。纯 CSS + 一个 line decoration，
跟剧本排版是同一套机制。

### 4.4 便利贴折叠成标签 【S】

贴到五六张就开始糊住稿纸。折叠成一个带名字的小色块，点开才展开。
`PinnedSticky` 里已经有 `collapsed` 字段，现在只是没做得够小。

### 4.5 会话产出：写了 / 删了 / 净 【S】

> 「搞成本次写了多少字、删除多少字、净产出多少字。」

顶栏右边显示三个数：**写了 1,240 · 删了 380 · 净 860**。

从 CodeMirror 的 changeset 里累计增删字数——比「前后字数一减」诚实得多：
改稿那天净产出可能是负的，而你确实干了一下午活。
**这正是要让他看见的东西**：删掉三百字不是没干活。

一次会话 = 从软件打开算起；顶栏那儿能手动清零重新计。

### 4.6 稿纸留白与首行缩进可调 【S】

已经能调字号、行距、页宽，补上下留白和首行缩进（有人不要缩进）。

### 4.7 导出增强 【M】——排版挪到这儿来了

> 作者原话：「实在不行，把空格这一项，整合进导出功能吧。」

**这个改法比原来那个好，而且好在根子上。**

原方案是「一键排版」直接改稿子：往文件里塞全角空格、插空行。
那要破第 2 条铁律（文件里不存全角空格），还带出一堆麻烦——
CSS 缩进会跟真空格叠成四格、排完要标记「这篇已手动缩进」、
撤销要能整体退回去。**每一条都是自找的。**

挪进导出之后这些全没了：**文件始终干净，排版只出现在导出的产物里。**
导出本来就是「给别人看的那一份」，排版属于那儿。
`03 §2` 那条铁律**一个字都不用改**。

#### 已经有的（0.1 就做了，我核对过）

| | 在哪儿 |
|---|---|
| **首行缩进两格** | `ExportOptions.indentFirstLine`，**默认开**，界面上也有开关 |
| 段落之间空几行 | `ExportOptions.paragraphSeparator`，字段有，**界面没暴露** |
| 章节之间空几行 | `chapterSeparator`，同上 |
| 包含章节标题 / 剧本排版 | 有，界面上有开关 |
| 移除伏笔标记 / 双链转纯文本 / 移除注释 | 有，都默认开 |
| txt（完整）/ docx / 分章 txt | `transfer.ts` |
| 只导某几章 | `collectForExport(bookPath, {fromPath, toPath})` |

所以「首行空两格」这件事**其实早就做好了**，只是长在导出里，
而作者一直在稿纸上找它。

#### 这一版要补的

**（1）格式加一档 md 【S】**

现在只有 txt / docx。加 md，规矩是作者定的：**md 保留语法，txt 不保留。**

但「保留语法」要说细一点——这两档默认值该是**反的**，因为用途是反的：

| | md | txt |
|---|---|---|
| 用途 | 我自己的备份 / 换个编辑器接着写 | 发给编辑、贴到平台 |
| `## 标题` | **保留** | 变成纯文字一行 |
| `[[李四]]` | **保留** | **按开关**（默认变成「李四」） |
| `<!--埋#玉佩-->` | **保留** | **按开关**（默认去掉） |
| `@浮出` | **保留** | **按开关**（默认去掉标记、留内容） |
| 首行缩进两格 | **不加**（源文件不该有） | **加** |

一句话：**md 是「原样搬走」，txt 是「排给人看」。**
两档都能逐项改，但默认值别一样——一样的话总有一档是错的。

> 作者定：**`@`、伏笔注释这些留不留，加开关让用户自己决定。**
> 伏笔（`stripForeshadow`）、双链（`stripWikiLinks`）、注释（`stripComments`）
> 三个开关**界面上早就有了**；`@` 那个是新加的（见下）。
> md / txt 只是给这几个开关一套不同的**默认值**，不是把它们写死。

**⚠️ 顺带发现一个漏子：`@` 现在根本没被处理。**

`renderBody()` 里认得伏笔、双链、注释、Markdown 语法，
**唯独没管 `@`** —— 也就是说导出给编辑的 txt 里，
行首那个 `@` 是原样带出去的。这不是「还没做的功能」，
这是**已有功能漏了一种标记**。0.4 顺手补上，并加开关。

**⚠️ md 档不能直接复用 `renderBody()`。**

它中间那一段是**无条件**把 Markdown 转成纯文本的（标题、粗体、引用、
代码、分隔线全剥），没有开关。md 要保留语法，就得让那一段能整块跳过。
加一个 `keepMarkdown` 选项，为真时**只做标记的取舍，不动排版语法**。

**（2）导出部分：正文 / 大纲 / 设定集 【M，这条是主要工作量】**

`collectForExport()` 现在只走 `tree.text`。`BookTree` 里另外还有：

```
outline: DocNode[]          大纲
settings: SettingCategory[] 设定集（按分类）
looseSettings: SettingCard[] 没归类的设定卡
```

要各写一个收集函数。三个部分**各出一个文件**，不是揉成一份——
设定集拼在正文后面发给编辑，那是帮倒忙。

选了多个部分就导成一个文件夹：

```
《索灵笔记》导出 2026-09-01/
  正文.txt
  大纲.txt
  设定集.txt          一个文件，分类当二级标题
```

**（3）几条转换补进 `renderBody` 【S】**

- 中英之间加空格：`写了3000字` → `写了 3000 字`
- 清理英数前后多余空格
- 段间空行 / 章间空行的开关**暴露到界面上**（字段本来就有）

**（4）一键导出 【S】**

记住上次选的那套选项，下次一个按钮走完。
导出这件事一个人的口味基本不变——每次重勾八个开关是纯浪费。

#### 要小心的

- **导出永远不动源文件。** 这条现在成立，加了排版之后也必须成立
- 导出前给**预览**（`previewExport()` 已经有了），别让他导完才发现排错了
- txt 继续带 BOM——不带的话 Windows 记事本会把中文认成乱码（0.1 踩过）

## 6. 做的顺序

§1 那个 bug 从「最大的工程」缩成了一个小修复，这一版因此宽裕不少。

1. **修拖便利贴插人名**（§1）——它在动作者的稿子，先修
2. **成就**（§2）——要改服务器 + 部署一次，中间有等待，早点起头
3. **外观三件**（§3.1 两处都能改、§3.2 砍到三档、§3.3 补充）——互相挨着，一起做
4. **打字机 + 智能替换 + 专注模式**（§4.1–4.3）——这一版体感提升最大的三条
5. **导出增强**（§4.7）——地基是现成的，主要是补 md 档和大纲/设定集的收集
6. **导入字体**（§3.4）、**便利贴折叠**（§4.4）、**会话产出**（§4.5）、**留白缩进**（§4.6）

## 7. 三个问题的结论（2026-09-01 已定）

| 问题 | 结论 |
|---|---|
| 横向打字机是什么 | **列始终在中间，稿纸横着动**。见 §4.1，附带要关掉自动折行 |
| 首行空两格 vs 第 2 条铁律 | **冲突取消了。** 排版整体挪进导出，源文件不动，03 §2 一个字都不用改。见 §4.7 |
| 奖状进不进公开接口 | **不进。只有本人看得见**，多个时在客户端切换挂哪个。见 §2 |

另外作者明确：**不要「管理员账户」这种东西。**
所以颁奖界面不进写作软件 ——
服务器那边只是一行 sub 名单，不是一个账号类型。

## 8. 导出那两个问题的结论（2026-09-01 已定）

| 问题 | 结论 |
|---|---|
| 设定集导成几个文件 | **一个文件**，分类当二级标题。它是拿来通读的，拆开反而难找 |
| `@`、伏笔注释要不要保留 | **加开关让用户决定。** md / txt 各给一套默认值，不写死 |

至此 0.4 的目标全部确定，没有待决事项了。

## 9. 做完之后跟计划的出入

| 计划里怎么说 | 实际怎么做 | 为什么 |
|---|---|---|
| §3.3「换主题时给一张即时预览」 | 把主题下拉框换成**三个色块按钮**，色块本身就是预览 | 砍到三档之后放得下了。下拉框选完才看得见，色块扫一眼就知道 |
| §2「发奖前先查短名存不存在」 | 服务端加了 `GET /api/v1/admin/awards?handle=` | 初版是拿「撤一张不存在的」把清单读回来 —— 一个 DELETE 其实是读，太脏 |
| 计划里没提 | `themeOf()` 加了退休表：墨灰→夜间、纸黄→纸白 | 砍档时才想到：原本「认不出退回纸白」会让用深色的人升级后一片惨白 |
| 计划里没提 | md 导出**不加 BOM**（txt 仍旧加） | 加了的话很多 Markdown 工具会把第一行的 `#` 当普通字符 |
| 计划里没提 | 折叠的便利贴缩成小名牌（不再占整张卡的宽度） | 原来的「折叠」只收正文，头部照样霸着位置，等于没解决糊住稿纸的问题 |

做了，但**只在设置页那一处说**；启动时自动装失败仍旧是静默的（那时候没有界面可说话）。
