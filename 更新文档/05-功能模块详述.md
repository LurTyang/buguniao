# 05 · 功能模块详述

## 1. 书架

| 能力 | 说明 |
|---|---|
| 扫描 | 启动时扫描根目录下所有含 `book.yaml` 的文件夹 |
| 分类 | 全部 / 连载中 / 完结 / 坑啦！哈哈（对应 `book.yaml` 的 `status`） |
| 封面 | 作品目录下的 `cover.jpg`；无封面时按书名首字生成占位色块 |
| 统计 | 卡片显示总字数、最后更新时间、今日增量 |
| 新建作品 | 创建标准目录骨架 + `book.yaml`，并生成一个空的第一章 |
| 归档 | 把作品移到 `_归档/` 子目录，书架默认不显示（不删除任何文件） |

## 2. 编辑器

**内核：CodeMirror 6，Markdown 源码模式 + 实时装饰。**

即：文件里存的是 `**加粗**`，编辑器里显示为**加粗**样式但保留标记符号可见（光标所在行显示原始标记，其他行隐藏标记）。这是 Obsidian「实时预览」的模式，兼顾所见即所得与纯文本可控。

| 能力 | 说明 |
|---|---|
| 性能 | 虚拟滚动，单文档 10 万字内保持流畅。超长章节给出拆分建议 |
| 自动保存 | 停止输入 **3 秒**后自动保存；切换文档、失焦、关闭窗口时强制保存 |
| 版本记录 | 每次保存写一条版本历史（见第 7 节）。连续保存间隔 < 30 秒时合并为一条 |
| 实时字数 | 顶栏显示当前文档字数（中文按字符计，不计标点与空白 —— 与起点等平台口径一致） |
| 中文写作优化 | 中文标点自动配对、书名号/引号智能补全、首行缩进用 CSS 实现（**不往文件里插全角空格**） |
| 拼写/敏感词 | 一期不做 |

**首行缩进的处理很重要：** 用 `text-indent: 2em` 的 CSS 实现视觉缩进，
文件里**不存**全角空格。导出时再按目标平台需要决定是否插入。
这样避免了正文里混入大量不可见字符，影响检索和 diff。

## 3. 目录与大纲

### 3.1 目录（正文标签）

- 卷（文件夹）→ 章（文件）两级；需要「节」时用文档内的 `##` 标题，在目录里可展开
- 显示每章字数、状态色点（草稿灰 / 完成绿 / 修订中黄）
- 拖拽排序 = 重命名文件的序号前缀（见 [03](03-数据格式规范.md) 第 1.1 节）
- 右键：新建章节、重命名、移动到其他卷、删除（进回收站，不硬删）

### 3.2 大纲

大纲是独立的 `.md` 文档（`type: outline`），不是从正文自动生成的。

- 大纲文档中用 `[[章节标题]]` 关联到具体章节，点击可跳转
- 编辑正文时，右侧「大纲」标签自动高亮当前章节对应的大纲条目
- **伏笔连线可视化（二期）**：在大纲视图上把「埋点章节 → 收点章节」画成曲线，
  默认关闭，通过开关打开。一期先用「未回收清单」代替

## 3.4 「这一篇在别处也改过」（2026-08-27 重做）

切回窗口时会看一眼磁盘上的这一篇变了没有 —— 作品文件夹就在同步目录里，
另一台电脑写的东西随时会同步进来。

### 初版会吞字，而且会误报

作者报的两件事其实是一个根因：

1. **同一台机器也会触发。** 判断用的是「磁盘 ≠ `loadedBody`」，
   而 `loadedBody` 只在**打开文档**时赋值 —— 自己保存之后它就过期了。
   于是每次切回窗口都判定成「在别处改过」。
2. **会吞掉一段没保存的文案。** 判定成立时它直接拿磁盘那版覆盖编辑器。
   平时覆盖的就是自己刚存的，看不出来；但在这个时序里会丢字：

   > 打字 → 没到自动保存就切走 → 切回来，焦点检查开始 `await readDoc`
   > → **等待期间那个被后台节流的自动保存刚好落地** → 检查继续往下走，
   > 此时 `saveState` 已经不是 `dirty` 了，于是拿**读盘那一刻的旧内容**
   > 覆盖了编辑器 —— 刚敲的那段没了。

### 现在怎么做

**判断**（三条，按顺序）：

| 情况 | 动作 |
|---|---|
| 磁盘 == 编辑器 | 什么都不做（自己刚存过的常态） |
| 磁盘 == 上次读到/写下的 | 什么都不做（只是我这儿有没保存的字） |
| 都不是 | 停下来，弹框让作者挑 |

保存时**同步更新 `loadedBody`**，误报的根就断了。
读盘期间自己刚好存过的话（比对存盘计数）**重读一遍** ——
不重读就是拿保存前的磁盘内容去比保存后的编辑器内容，永远不一样。

**绝不自动覆盖。** 弹框里摆出两版的：

- 设备名（`front-matter` 里新增的 `device`，默认取主机名）
- 字数
- 修改时间
- 前 120 字的样子

两个按钮：**保留我这版**（默认，Esc 也是它）／**用磁盘那版**。
点遮罩不关 —— 这是个要做决定的框，手滑点到外面就消失反而更吓人。

**选「用磁盘那版」时，先把屏幕上这版另存成同目录下的一篇**
（`原标题（本机未保存 08-27 0140）`），再换。
不管怎么选，一个字都不丢。

> 一个写作软件吞掉一次文字，作者就再也不敢用它了 ——
> 这比任何功能缺失都严重。所以这里宁可多问一句。

## 4. 设定集与便利贴

语法规范见 [03-数据格式规范](03-数据格式规范.md) 第 4 节。本节只讲行为。

| 能力 | 说明 |
|---|---|
| 解析时机 | 文件保存时 / 索引重建时解析，结果缓存进索引库 |
| 分类 | 靠**文件夹**组织（人物/势力/功法/地点…），文件夹名即分类名，作者自由增删 |
| 新建便利贴 | 选择分类 → 套用该分类的模板 → 生成待填写的骨架文档 |
| 搜索 | 便利贴列表顶部搜索框，匹配标题 + 浮出内容 + 全文 |
| 悬浮 | 见 [04](04-界面与交互设计.md) 第 3 节 |
| 反向链接 | 每张便利贴底部显示「被哪些章节引用」，由索引库的 `[[]]` 关系表提供 |

**一个设定集文档 = 一张便利贴。** 不做「一个文档拆多张卡」——
想要多个角色就建多个 `.md`，靠下面的模板系统把新建成本降到近乎为零。

### 4.1 分类模板（作者指定的核心需求）

每个分类文件夹可以有自己的模板。新建时自动套用，作者只需填空。

**模板存放：** `设定集/{分类名}/_模板.md`
以 `_` 开头的文件不参与便利贴扫描，所以模板本身不会变成一张卡。

```markdown
设定集/
├── 人物/
│   ├── _模板.md          ← 这个分类的模板
│   ├── 李四.md
│   └── 王五.md
├── 配角/
│   ├── _模板.md          ← 配角有自己的模板，比主角简略得多
│   ├── 药铺掌柜.md
│   └── 看门的老张.md
└── 功法/
    └── _模板.md
```

**模板内容示例**（`设定集/配角/_模板.md`）：

```markdown
# {{标题}}

@身份：@
@首次出场：@

## 外貌

## 与主角的关系

## 备注
```

| 占位符 | 替换为 |
|---|---|
| `{{标题}}` | 新建时输入的名字 |
| `{{日期}}` | 当天日期 |
| `{{分类}}` | 所在分类文件夹名 |

**交互流程：**
1. 右侧边栏「设定集」标签 → 点某个分类（如「配角」）→ `+ 新建`
2. 输入名字「药铺掌柜」
3. 自动生成 `设定集/配角/药铺掌柜.md`，套用模板并替换占位符
4. 光标落在第一个空处，直接开始填

**点击分类节点可查看该分类下所有便利贴** —— 点「配角」就列出全部配角卡片，
支持网格视图（看卡片正面）与列表视图（看标题）切换。

**没有模板时**：生成最简骨架（front-matter + `# 标题`），不阻塞。
**编辑模板**：在分类上右键 →「编辑本类模板」，不存在时自动创建一份默认的。

## 5. 伏笔追踪

数据格式见 [03](03-数据格式规范.md) 第 5 节。三种录入方式**都要有**：

### 5.1 正文中标记（`Ctrl+E`）

1. 选中正文中的一段
2. 弹出小窗：填「伏笔标题」「描述」「大致回收时间」「优先级」
3. 确认后，正文中被包上 `<!--埋#id-->…<!--/埋#id-->`，元数据写入 jsonl

回收时用 `Ctrl+Shift+E`，弹窗里从**未回收清单**中选一个伏笔关联。

### 5.2 独立清单先记后写

在左侧边栏「🪤 伏笔」面板里直接「+ 新建」，此时 `status: planned`、`plantedIn: null`。
将来写到正文时，选中文本 → `Ctrl+E` → 从清单里选中它 → 状态自动变 `planted`。

### 5.3 到期提醒

`expectBy` 可以填：
- 自由文本（「第三卷」「主角出师后」）—— 仅作参考显示，不触发提醒
- 具体章节 —— 当作者打开或写到该章之后的章节时，**在顶栏显示一条不打断的浅色提示条**：
  「有 2 个伏笔计划在此之前回收」，点击展开清单

> **注意：这是提示条，不是弹窗。** 桌面端不做任何打断式提醒（见 [01](01-产品定义与范围.md) 第 6 节）。

### 5.4 未回收清单

默认视图。按优先级 + 埋设时间排序，显示：
标题 / 描述 / 埋在哪章（可点击跳转）/ 已经过去多少章 / 计划回收点。

「已经过去多少章」是最有用的一列 —— 埋了 80 章还没收的伏笔一眼就能看见。

### 5.5 AI 抓漏（手动触发）

「让 AI 扫一遍」按钮：把全书正文（或指定卷）+ 未回收清单发给 AI，
让它指出「哪些伏笔看起来已经在正文里被回收了但没标记」以及
「哪些悬而未决的线索没有登记成伏笔」。结果以清单形式呈现，作者逐条决定是否采纳。

## 6. 全文检索

- 引擎：SQLite FTS5 + `trigram` 分词（见 [02](02-技术架构.md) 第 4 节）
- 范围筛选：正文 / 大纲 / 设定集 / 灵感碎片，可多选
- 结果显示：文档标题 + 上下文片段（关键词高亮）+ 所在位置，点击跳转并定位
- 高级：支持 `卷:第一卷` `章:坠楼` 这类字段限定前缀
- 查询串 < 3 字符时降级为 `LIKE` 扫描（数据量小，仍是毫秒级）

**索引更新时机：** 文件保存后立即增量更新该文档的索引；
文件监听器发现外部修改（比如你用记事本改了）时也触发重建该文档索引。

**索引重建入口：** 设置 → 维护 → 「重建索引」。全量重扫，百万字约 20~40 秒。

## 7. 版本历史

数据格式见 [03](03-数据格式规范.md) 第 6 节。

| 能力 | 说明 |
|---|---|
| 列表 | 按时间倒序，显示时间、字数变化（+842 / −120）、标记名 |
| 对比 | 选中任意两版并排 diff，增删用颜色区分 |
| 回滚 | 恢复到某版本。**回滚本身也产生一条新版本记录**，所以回滚可以再撤销 |
| 打标记 | `Ctrl+Shift+S` 或在列表里右键，给版本起名（如「完成第一卷」） |
| 筛选 | 「只看带标记的版本」开关 |
| 容量 | 顶部显示 `已用 312 MB / 上限 500 MB`，超 80% 变黄，超 100% 变红 |

**超上限时的行为（重要）：**
1. 红色横幅提示，且**暂停写入新的版本记录**（正文保存不受影响）
2. 提供三个按钮：`提高上限` / `清理旧版本` / `只保留带标记的版本`
3. **绝不静默删除任何历史**

## 8. 统计与番茄钟

### 8.1 统计

数据来源：`.bugu/stats/*.jsonl`（见 [03](03-数据格式规范.md) 第 7 节）。

#### 「今天」是怎么算的（作者定稿，与日历不同）

**「今天」不按日历切，按写作会话切：**

> 凌晨 4 点之后的**首次落笔**（或中断半小时以上后的再次落笔），才开启新的一天。
> 这一场写下去的所有字都算这一天的 —— 哪怕一时兴起写到第二天中午十二点。

判定顺序是**先切会话，再给会话定日期，记录跟着会话走**，而不是给每条记录单独定日期。

| 情形 | 归属 |
|---|---|
| 周一 22:00 开写，连续写到周二 12:00 | 整场算**周一** |
| 周一 23:00 写到周二 01:00，停两小时，03:00 又写 | 两场都算周一（03:00 还没到 4 点） |
| 周二 03:50 停笔，05:00 再写 | 05:00 那场算**周二** |

#### 签到与补签（作者定稿）

| 门槛 | 效果 |
|---|---|
| 当日写够 **5,000 字** | 签到成功，计入连续天数 |
| 当日每写够 **10,000 字** | 额外获得 1 次**补签额度** |

补签额度用来**回补之前漏掉的日子**，让连续天数接得上。两条约束：

1. **额度只能补更早的日子** —— 这是「补签」的本义，不能预支未来
2. **额度补不上的地方就是真断了，断点之前攒的额度作废** —— 不允许攒一大笔额度
   去跨过一个大坑修补很久以前的历史，那样连续天数就没有意义了

界面上补签来的日子要**明确标出来**（热力图上用不同的标记），
并如实显示「当前连续 25 天，其中 3 天是补签的」。数字要诚实。

两条门槛都可在设置里改；补签线设为 0 即关闭补签。

#### 视图

| 视图 | 说明 |
|---|---|
| 今日 | 今日字数 / 目标（`book.yaml` 的 `dailyWords`）/ 完成百分比 / **还差多少字签到** |
| 曲线 | 日 / 周 / 月字数折线，可切换「本书」与「全部作品」 |
| 热力图 | GitHub 风格年度日历热力图，颜色深浅按**分位数**分级（不用固定阈值，否则日更三千和日更三万的作者总有一个整片死绿）；补签日单独标记 |
| 会话 | 每场写作的时长、字数、平均速度（字/小时）、是否通宵 |
| 连续天数 | 当前连续 + 历史最长 + 其中几天是补签的 |

### 8.2 番茄钟

- 默认 25 分钟专注 + 5 分钟休息，可配置
- 专注期间可选自动进入沉浸模式（隐藏所有侧边栏）
- **桌面端结束时不弹窗**，只在顶栏做一次柔和的颜色渐变提示 + 可选提示音
- 番茄钟期间的保存记录带 `pomo: true`，可以统计「番茄钟内的产出效率」

**两条体贴之处（已实现并有测试锁死）：**
- **今天还没写不算断更** —— 今天才刚开始，连续天数从昨天起算
- 但**昨天也没写就是真断了**，不粉饰。净增字数为负的那天同样不算「写了」

#### 计时不能住在面板里（2026-08-27 修）

侧边栏是**划出来的**，收起来时整个面板 `return null` —— 状态放在组件里，
表现出来就是「番茄钟开着，鼠标挪开一下，回来发现归零了」。
作者报的就是这个。

而且不止归零：面板关着时「到点了」那段逻辑也不跑 —— 专注结束不会自动
进休息、不会响、不会计数。等于番茄钟只在你盯着它看的时候才走。

所以状态和那个 interval 一起挪到模块级（`renderer/pomodoro-store.ts`），
面板只是它的一个视图。顶栏那个小胶囊也直接订阅它，
不再靠面板回调 —— 面板关着时回调就断了，胶囊会停在最后一帧。

那个 store **刻意不 import 任何东西**（不碰 `api`、不碰 React），
所以计时逻辑能在 node 环境里直接测（16 个测试）。
要响一声、要告诉主进程在不在专注，由外面注入。

### 8.3 手机端提醒

只有手机端做主动推送（Capacitor Local Notifications）：

| 提醒 | 默认 | 说明 |
|---|---|---|
| 每日提醒 | 关 | 可设时间，如 21:00「今天还没开张」 |
| 断更提醒 | 关 | 连续 N 天（默认 3）没有写作记录时推送 |
| 番茄钟结束 | 开 | 仅在手机端跑番茄钟时 |

所有提醒默认关闭，由作者自己开。文案可以有点自嘲感，但不要说教。

## 9. AI 助手

### 9.1 总体约束

- **仅桌面端提供**（一期）。理由：API Key 需要在 Electron 主进程里保管，
  Android 的 WebView 环境无法安全存放密钥并直接调用
- **总开关默认关闭**，首次使用需要作者主动开启并填入 API Key
- 所有调用**手动触发**，无后台任务
- AI 输出进入独立面板，**绝不直接写入正文文件**

### 9.2 服务商（已实现）

**默认走 OpenAI 兼容端点**，不是 Claude。

「OpenAI 兼容」指的是提供 `/v1/chat/completions` 的服务 ——
DeepSeek、Gemini、月之暗面、本地跑的 Ollama / vLLM 都算。
所以唯一不能写死的就是**端点地址**，它必须由作者填。

| 服务商 | 实现 | 联网搜索 | 数 token |
|---|---|---|---|
| **OpenAI 兼容端点**（默认） | `openai` SDK，只改 `baseURL` | ✗ | 没有这个接口，本地粗估 |
| Anthropic Claude | `@anthropic-ai/sdk` | ✓ | `messages.countTokens`，精确 |

界面上四个字段，两家一样：**服务商 / 端点地址 / 模型名 / API Key**，
外加一组**单价**（每百万 token 的进价与出价）。

模型是个**下拉框**，列表里没有的（新出的、自建的）选「自己填…」再打字。
**每家都是便宜的排在前面，第一款就是默认值** —— 资料员这活儿多数时候用不着
旗舰模型，默认给个贵的等于替作者做了一个他没同意的花钱决定。
换模型时三档单价跟着换。

| 预设 | 端点 | 模型（默认是第一款） | 计价 |
|---|---|---|---|
| DeepSeek | `https://api.deepseek.com/v1` | `deepseek-v4-flash`、`deepseek-v4-flash-vision-exp`、`deepseek-v4-pro` | ¥，分高峰/空闲 |
| 智谱 GLM | `https://api.scnet.cn/api/llm/v1` | `GMP-5-Base` | ¥，单价待填 |
| Gemini | `https://generativelanguage.googleapis.com/v1beta/openai` | `gemini-2.5-flash`、`gemini-2.5-pro` | $ |
| OpenAI | `https://api.openai.com/v1` | `gpt-5-mini`、`gpt-5` | $ |
| 其它 | 空，自己填 | 空，自己填 | 自己选 |
| Anthropic | `https://api.anthropic.com` | `claude-haiku-4-5`、`claude-sonnet-5`、`claude-opus-5` | $ |

> 模型名后面**不写「便宜」「贵」这类括号**，服务商下拉框**底下也不写介绍小字**。
> 作者原话「大可不必」—— 选它的人自己清楚，价钱看下面的单价栏。

**端点地址会自动收拾。** 作者多半是从服务商文档里整条复制过来的，比如
`https://api.scnet.cn/api/llm/v1/chat/completions`；直接用会拼成两遍
`/chat/completions` 然后报 404，而地址看起来完全正确，很难查。
失焦时自动去掉结尾的 `/chat/completions`、尾斜杠和查询串。

### 9.2.1 代理（必须有）

**Node 自带的 `fetch` 不认 `HTTP_PROXY` / `HTTPS_PROXY` 环境变量。**
作者机器上开着代理、浏览器能开 Google，软件里连 gemini 却一直超时，
就是因为请求根本没走代理。

实测（2026-08-25，作者机器）：

| 端点 | 直连 | 经代理 |
|---|---|---|
| `api.deepseek.com` | HTTP 401（通） | 通 |
| `generativelanguage.googleapis.com` | 超时 | 通 |
| `api.openai.com` | 超时，且 DNS 解析到不相干的地址 | 通 |

所以设置里有一项**代理**：`auto`（读环境变量，默认）/ `off` / 直接填地址。
下面一行永远显示**实际生效的是什么**，还有一个「测试连接」按钮 ——
不带 Key 地试连端点，回答「到底是墙、是地址错，还是 Key 错」。

> 实现上必须用 undici **自带的 fetch**，不能把 undici 的 ProxyAgent 塞给全局 fetch：
> Node 24 内置 undici 7.x，装进来的是 8.x，dispatcher 接口对不上，
> 会报 `invalid onRequestStart method`。

### 9.2.2 单价与计费

单价分**三档**填，因为**缓存命中与未命中的输入价能差三十倍** ——
DeepSeek v4-flash 是每百万 token 命中 0.10 元、未命中 3.00 元。
用「命中价 = 未命中价的十分之一」这种拍脑袋的比例去算，会把花销高估三倍。

| 档 | 说明 |
|---|---|
| 输入 | 缓存未命中 |
| 输入·命中缓存 | 单列 |
| 输出 | —— |

另外两件事：

- **币种可选**（¥ / $）。DeepSeek、智谱按人民币报价，Gemini、OpenAI 按美元。
  累计用量**按币种分开记** —— 人民币和美元加在一起是个没有意义的数字。
- **空闲时段半价**（DeepSeek 有，勾选启用）。高峰为
  **北京时间**周一至周五 9:00–12:00、14:00–18:00，其余时段自动按半价算。
  按北京时间而不是本机时区判断 —— 作者可能人在别处，但服务商的时段是按北京时间定的。
  写手常写到凌晨，那一段正好是半价。

单价全填 0 表示「不知道」，那就只报 token 数，不编金额。智谱默认就是这样。

**DeepSeek 的内置单价**（作者 2026-08-25 提供的官方价目表，每百万 token，人民币）：

| 模型 | 输入·命中缓存 | 输入·未命中 | 输出 |
|---|---|---|---|
| `deepseek-v4-flash` | 高峰 0.10 / 空闲 0.05 | 高峰 3.00 / 空闲 1.50 | 高峰 9.00 / 空闲 4.50 |
| `deepseek-v4-flash-vision-exp` | 同上 | 同上 | 同上 |
| `deepseek-v4-pro` | 高峰 0.30 / 空闲 0.15 | 高峰 9.00 / 空闲 4.50 | 高峰 27.00 / 空闲 13.50 |

代码里**只记高峰价**，空闲价由 `offPeakDiscount = 0.5` 算出来 ——
存两份迟早对不上，而且这一半的关系是官方明写的规则。

### 9.2.3 面板上的两处体贴

- **填过 Key 之后，设置区默认收起**，只留一行「设置　DeepSeek · deepseek-v4-flash」。
  端点、模型、单价是一次性设好的东西，天天摊在面板底下只会挤掉正经内容。
- **跑起来的时候显示已经想了多少秒。** 抓虫、长章节续写动辄一两分钟，
  没有这个数就分不清是在想还是卡死了。跑完在花销那一行也报总用时。

**单价为什么让作者自己填**：各家随时调价，写死在代码里迟早骗人。
填 0 表示「不知道」，那界面就只报 token 数，不编一个金额出来。

**每家各存一个 Key。** 换服务商不该逼作者重填 —— 换回来还要再填一遍。

**联网搜索只有 Anthropic 有。** 换到别家时开关灰掉，
并在下面写清楚为什么 —— 不写原因的话，作者只会觉得这个开关坏了。

**数 token 只有 Anthropic 精确。** OpenAI 兼容端点没这个接口，
估价时退回本地粗估（中日韩约 1 字 1 token，拉丁约 4 字符 1 token），
界面上如实标明「这家没有数 token 的接口，上面是本地按字数粗估的」。

代码分三个文件：`ai-provider.ts`（接口与预设）、`ai-openai.ts`、`ai-anthropic.ts`；
`ai.ts` 只管跟服务商无关的部分（上下文怎么拼、费用怎么记）。

### 9.3 请求基本形态

```typescript
// ⚠️ 必须在 Electron 主进程执行，渲染进程通过 IPC 调用。
// 绝不要在渲染进程里 new Anthropic()，那会把 Key 暴露在前端。
import Anthropic from "@anthropic-ai/sdk";

const client = new Anthropic({ apiKey: /* 从 safeStorage 解密取出 */ });

const stream = await client.messages.stream({
  model: "claude-opus-5",
  max_tokens: 64000,
  thinking: { type: "adaptive", display: "summarized" },
  output_config: { effort: "high" },   // low | medium | high | xhigh | max
  system: [
    { type: "text", text: WORLD_CONTEXT, cache_control: { type: "ephemeral", ttl: "1h" } },
  ],
  messages: [...],
});
const response = await stream.finalMessage();
```

**要点：**
- 长上下文场景**必须用 `.stream()`**，否则容易撞 HTTP 超时
- `thinking: { type: "adaptive" }` 是当前 API 的写法，**不要用旧的 `budget_tokens`**（会返回 400）
- `display: "summarized"` 才会返回可读的思考摘要；默认是 `omitted`（思考照常发生并计费，只是不返回文本）
- 强度用 `output_config.effort` 调，不用 `budget_tokens`

### 9.4 上下文组装（资料员的核心）

作者问「这里我会死吗」时，AI 需要知道「主角正从 48 楼掉下」。上下文按下列顺序拼装：

| 层 | 内容 | 是否缓存 |
|---|---|---|
| 1 | 系统提示：你是这本书的资料员，规则若干 | ✅ 缓存 |
| 2 | **全部设定集**的浮出内容（便利贴正面，压缩过的） | ✅ 缓存 |
| 3 | 大纲全文 | ✅ 缓存 |
| 4 | 未回收伏笔清单 | ✅ 缓存 |
| 5 | 当前章节全文 + 前 2 章全文 | ❌ 不缓存 |
| 6 | 由问题触发的 FTS5 检索结果（相关章节片段 top 8） | ❌ 不缓存 |
| 7 | 作者的问题 | ❌ 不缓存 |

**缓存分界线放在第 4 层之后。** 1~4 层内容在一次写作会话中基本不变，
用 `cache_control: { type: "ephemeral", ttl: "1h" }` 缓存后，
后续每次提问只按 ~10% 价格计这部分 token，成本下降一个数量级。

> **缓存失效陷阱：** 系统提示里绝不能放时间戳、随机 id 之类每次都变的东西 ——
> 前缀有一个字节变化，后面全部缓存作废。上线后用 `usage.cache_read_input_tokens`
> 验证：如果它一直是 0，说明有东西在悄悄破坏缓存。

### 9.5 联网搜索

用 Anthropic 的服务端工具，不需要自己接搜索引擎：

```typescript
tools: [{
  type: "web_search_20260209",
  name: "web_search",
  max_uses: 5,
  // 可选：allowed_domains / blocked_domains / user_location
}]
```

- **默认关闭**，在 AI 面板上有独立开关，每次会话可切换
- 用途：查资料（「明代四品官的俸禄是多少」「珠穆朗玛峰的含氧量」）
- 结果块类型是 `web_search_tool_result`
- ⚠️ 使用 `_20260209` 变体时**不要**再单独声明 `code_execution` 工具（它内部已包含）
- ⚠️ 搜索出错**不会抛异常**，而是返回 HTTP 200 且 `content` 变成一个错误对象
  （成功时 `content` 是数组）。取值前必须先判断类型

### 9.6 四项能力

| 能力 | 触发 | 行为 |
|---|---|---|
| **资料员问答** | AI 面板输入问题 | 按 9.4 组装上下文，流式回答。可开联网搜索 |
| **续写** | 光标处右键 → 续写 | 生成 **3 个不同方向**的续写版本，并排展示，作者可复制或忽略 |
| **润色** | 选中段落 → 右键 → 润色 | 给出润色版 + 修改点说明，并排 diff 展示，**不自动替换** |
| **抓虫** | AI 面板 → 抓虫 → 选范围 | 检查前后矛盾、人设崩坏、时间线错误、伏笔遗漏。输出清单，每条带原文定位 |

**所有输出的落地方式统一为：** 展示在面板里 → 作者点「采纳」→ 才写入正文。
没有任何一条路径能让 AI 直接改稿。

### 9.7 成本控制

- 设置里显示**本月累计消耗**（按 `usage` 字段自行统计，不依赖服务商账单）
- 可设**单月费用上限**，达到后禁用 AI 功能并提示
- 每次调用前，在按钮上显示预估 token 数（用 `client.messages.countTokens()` 算，别用 `tiktoken`）
- 「抓虫全书」这类大开销操作，执行前必须弹确认框并显示预估费用

> **粗略参照：** 中文 1 个汉字约 1~1.5 token。一次带 3 万字上下文的问答，
> 输入约 4 万 token，Opus 5 未命中缓存约 $0.2，命中缓存后约 $0.02。

### 9.8 错误处理

用 SDK 的类型化异常，从具体到宽泛依次捕获，**不要用字符串匹配错误信息**：

```typescript
catch (e) {
  if (e instanceof Anthropic.AuthenticationError)  // Key 错了 → 引导去设置页
  else if (e instanceof Anthropic.RateLimitError)  // 限流 → 提示稍后重试
  else if (e instanceof Anthropic.APIError)        // 其他 API 错 → 显示 status
  else                                             // 网络等 → 提示检查网络
}
```

## 10. 导入导出

### 10.1 导入：大块 txt 自动分章

这是最容易出错的功能，因为正文里也可能出现「第三章」字样。**判定策略：**

| 条件 | 权重 |
|---|---|
| 该行**独占一行**（去空白后整行就是标题），且长度 ≤ 40 字 | 必要条件 |
| 匹配 `^第[0-9零一二三四五六七八九十百千万]+[章节回]` 等标题模式 | 必要条件 |
| 前后有空行 | 加分 |
| **序号在全文中单调递增** | **决定性** |

**「单调递增」是最强的信号。** 正文里偶然提到的「他想起第三章说的话」不会构成
一条从 1 递增到 300 的完整序列，因此会被自动排除。

**流程：**
1. 选文件 → 自动检测编码（UTF-8 / GBK，中文 txt 常见 GBK）
2. 扫描候选分章点 → 计算最优递增序列
3. **预览界面**：左边列出识别到的所有章节，右边显示每章开头 200 字，
   作者可以手动**增删分章点**、批量改标题格式
4. 确认后生成文件，自动补 front-matter 与序号前缀

### 10.2 导出

| 格式 | 状态 | 说明 |
|---|---|---|
| 完整 txt | ✅ 已实现 | 合并全书，**带 BOM 导出** —— 不带的话 Windows 记事本会把中文认成乱码 |
| Word (.docx) | ✅ 已实现 | 卷用「标题 1」、章用「标题 2」，编辑能用导航窗格跳转；首行缩进走段落样式，不往正文塞全角空格 |
| 按章分文件 | ✅ 已实现 | 每章一个 txt，文件名带四位序号保证上传顺序不乱 |
| Markdown 原样打包 | 未做 | 直接复制作品文件夹即可，优先级最低 |

**导出选项（对所有格式通用）：**
- 是否移除伏笔标记注释（默认**移除**）
- 是否移除 `[[链接]]` 语法（默认转为纯文本）
- 是否插入首行全角空格（默认插入，因为多数平台需要）
- 导出范围：全书 / 指定卷 / 指定章节区间

### 11.1 冲突副本怎么处理（已实现）

坚果云不会替你合并。两台电脑离线各写一版，它把后到的那份改名存下来 ——
`0010-第一章 (冲突文件 2026-08-25 明听).md` —— 然后就不管了。

软件做的事只有一件：**把两边摊开给作者看，让他自己挑**。

- 顶部黄条报出数量，点「并排看看」打开对比
- 左栏是这台电脑上的正本，右栏是同步下来的副本，逐行对齐，只有一边有的那行染色
- 三个按钮：**用左边** / **用右边** / **两份都留**

三条路都不硬删任何东西：

| 选择 | 发生了什么 |
|---|---|
| 用左边 | 正本一个字不动，副本进回收站 |
| 用右边 | **正本整个移进回收站**，再把副本的内容写到正本位置（文档 id 不变，版本历史和伏笔还挂在同一篇上） |
| 两份都留 | 副本变成一篇正常文档 `xxx（另一版）`，作者自己慢慢合 |

> 界面上刻意**没有**「自动合并」按钮。那个按钮猜错一次，
> 丢掉的就是作者熬夜写的那一版。

> 「用右边」为什么要先把正本移进回收站，而不是靠版本历史兜底：
> 历史按 30 秒时间桶合并，刚保存完就处理冲突的话，
> 被换掉的那一版会并进同一条记录里，**根本不留痕迹**。见 D-17。

## 12.5 作品类型（已实现）

新建作品时问一句「写的是小说、剧本，还是游戏剧本」，
**开局就套对应的骨架**。写完三章才发现「原来还有剧本模式」，
那时候格式已经写歪了。

| 类型 | 开局 | 界面上的差别 |
|---|---|---|
| **小说** | 空的「第一章」 | 就是原来的样子 |
| **剧本** | 「第一场」+ 场景标题骨架 | 剧本排版默认开着；右键菜单多一组剧本符号 |
| **游戏剧本** | 「第一幕」+ 一份体检全绿的分支骨架 | 右键菜单多一组游戏剧本符号 |

剧本和游戏剧本还会**顺手把设定集的「人物」分类建好**，并在 `book.yaml`
里指过去 —— 不然作者得先自己去找那个开关，「角色名单独排一行」
这件事就永远不会发生。

> **只在书架页右键这本书改，稿纸页里没有这个入口。**
> 换类型会换掉整本书的排版规矩，那不该是写到一半顺手点到的东西。

类型写在 `book.yaml` 的 `kind`。老书没有这一项，按小说算 ——
右键菜单里的游戏剧本符号仍然按「正文里有没有 `->`」来判，
老书的行为一个字没变。

## 13. 剧本模式（已实现）

格式见 [03-数据格式规范 · 剧本格式](03-数据格式规范.md#剧本格式)。
功能栏里的「剧本模式」面板做三件事：

| 项 | 说明 |
|---|---|
| **剧本排版** | 开关。只改显示，不动文件一个字节；关掉就是原来的纯文本 |
| **谁的戏多** | 按台词字数排序的条形图，点一下跳到他第一次说话的地方 |
| **谁好久没出声了** | 某个角色连着几场一句话都没有 |
| **场次** | 每场的标题、台词条数、字数、主场是谁；点一下跳过去，右边一对 ↑↓ 挪位置 |
| **角色名从哪儿来** | 勾设定集里哪几个分类算「人物」，可多选。见 §13.5 |
| **不在人物卡里的名字** | 抓写错的人名。见 §13.6 |

顶上一行概况：几场、几个角色、台词多少条多少字、动作与叙述多少字。

「谁的戏多」是剧本作者最想知道的一个数：**谁被写多了，谁被写没了**。
所以默认按台词字数排，不按出场顺序。

### 13.1 谁好久没出声了

群像戏最怕「某个角色连着五场一句话都没有」。
这个数**只看总台词量是看不出来的** —— 一个角色可以总字数很高，
却全挤在前三场。所以要摊到场上算：每个角色相邻两次开口之间隔了几场，
取最大值，隔了两场以上才列出来。

### 13.2 场次重排

每一场右边一对 ↑↓，把整场（标题 + 底下所有内容）挪个位置。

**这个操作直接改正文** —— 场次顺序**就是**正文里的顺序，
没有另存一份顺序数据，所以不会出现「面板里是这个顺序、文件里是那个顺序」。
挪之前先把编辑器里没存的内容刷进文件，再整段重写。

刻意**不做拖拽**：这是会改文件的操作，点错一下比拖错一下好收拾。
而且它走完整的保存管线，版本历史里留得下这一步，挪错了能回滚。

### 13.3 剧本模板

台词一条都还没有时，面板给一个「新建一篇，带骨架」的按钮。
骨架里有两场、场景标题（`内景·咖啡馆·日`）、动作行、带括号的表演提示，
照着填就是对的格式 —— 比让作者去读格式文档管用。

### 13.4 导出时套剧本排版

「导入 / 导出」浮层里多一个开关「剧本按剧本排版」：
场景顶格、动作缩两格、角色名缩四格、台词缩六格。

只对**看着像剧本**的章节生效。一本小说里夹着两章剧本很常见，
无条件套上去会把正常章节排得莫名其妙。

### 13.5 认人：角色名单独排一行 ⭐

`角色名：台词` 这条规矩靠正则是**猜**出来的 —— 卡得再死也挡不掉
「时间：三年后」「注意：这里要改」。而作者的**设定集里本来就写着
这本书有哪些人**，把那份名单读进来，「李四」就是确凿的角色名。

面板上「角色名从哪儿来」一排可勾的分类，**可多选** ——
有人把角色拆成「主要人物」「配角」两个文件夹，也有人叫「角色卡」。
选择存进 `book.yaml` 的 `castFrom`，跟着书走。

| 从哪儿取名字 | 说明 |
|---|---|
| 卡片名 | `李四.md` → 李四。`01-李四（男主）.md` 也认，编号和括号会去掉 |
| 别名行 | 卡里写一行 `别名：小李、李哥`。`又名 / 绰号 / 小名` 都认 |

带标点的、超过十个字的卡片名不当名字 —— 那是作者拿卡片名写了一句话，
混进名单会把一整句叙述排成角色名。

**认出来之后，那一行显示成两行**：

```
    李四
      你等很久了？
```

名字缩四格、台词缩六格，冒号藏起来（光标停在这一行时不藏 ——
正在改的那行如果字符会凭空消失，退格删到哪儿全靠猜）。
靠 CSS 的 `display:block` 做，**文件里还是那一行**，关掉排版就回去了。

**不在名单里的名字不拆行。** 拆错了就是把一句叙述从中间劈成两半。

### 13.6 这些名字不在人物卡里

说了话、但人物卡里没有的名字，单列一组。抓的是**写错的人名**：
「李西」和「李四」在统计表里是两个人，而作者盯着那张表根本看不出来 ——
两行长得几乎一样。

没勾任何人物分类时**一条都不报** —— 那种情况下每个名字都「不在卡里」，
报出来全是噪音。

## 14. 游戏剧本（已实现）

格式见 [03-数据格式规范 · 游戏剧本格式](03-数据格式规范.md#游戏剧本格式)。
功能栏「游戏剧本」面板，顶上是**写作进度条**，下面三个页签。

### 进度

`已写内容的节点 / 总节点（百分比） · 总字数 · 选项数 · 结局数`。
只有一个标题的节点算「空壳」，不计入已写。

### 节点

全书所有节点一张清单：名字、在哪个文件、多少字、出口跳到哪。
标着「起点」「空壳」「走不到」。点一下**跳到那个文件的那一行**。

### 体检 ⭐

这个面板真正的价值在这里。分支剧情最会咬人的六种毛病：

| 毛病 | 什么意思 |
|---|---|
| **断头路** | 跳到一个不存在的节点 |
| **孤儿** | 没有任何地方跳到它，玩家走不到 |
| **死路** | 没有出口，又不是结局，玩家卡在那儿 |
| **重名** | 两个节点同名，跳转不知道去哪个 |
| **条件写坏了** | `{}` 里的东西看不懂 |
| **变量没赋过值** | 条件用到一个全书从没赋过值的变量 —— 那条分支永远走不到 |

每一条都带着文件与行号，点一下跳过去。

**几十个文件里靠人眼是翻不出这些的。**
写完一整条线才发现某个结局根本拿不到，那是几万字白写。

### 结局

从起点真的走一遍（按「节点 + 变量状态」去重的广度优先），
列出所有走得到的结局，每个给**一条示例路径**：

```
初见 —点头→ 承认 → 放学 —一起走→ 结束      好感度=1
```

> ⚠️ 带变量的剧本状态空间会爆炸，所以有上限（默认两万个状态）。
> 超了会**在界面上明说「不是全的」** —— 作者拿这个判断
> 「这个结局拿不到」，糊弄他会让他白写几万字。

### 模板

节点清单为空时给一个「新建一篇，带骨架」的按钮。
骨架里有分支、变量、条件、结局，而且**它自己的体检是全绿的** ——
给作者一份自带断头路的模板等于教他写错。

### 14.1 分支节点图（已实现）

「图」页签。**从上往下分层**：层号 = 从起点走过来的最短步数，
同一层的节点横着排开。剧情是往下推进的，这个方向读起来最顺。

| 画法 | 意思 |
|---|---|
| 粗边框 | 起点 |
| 圆角胶囊 | 结局 |
| 虚线框 | 空壳节点（只有标题） |
| 红框 | 从起点走不到 |
| **虚线** | 往回跳。实线画回去会绕一大圈，图立刻变成一团毛线 |

鼠标停在一个节点上，跟它相连的线会高亮 —— 图一大，
看清「这个节点通向哪」全靠它。点节点跳到正文那一行。

选项文字**只在线不多（≤18 条）或鼠标悬停时**显示，
否则几十个标签会糊成一片。

> 布局算法在 `core/graphlayout`，有 29 个测试。
> 「哪个节点摆在哪」很容易悄悄算错 —— 环状跳转把层数算成无穷、
> 孤儿节点被摆到画布外面 —— 这些用眼睛看图是发现不了的。

### 14.2 块级条件（已实现）

条件本来只能挂在单条选项或跳转上，一段里有五条选项都要同一个条件时，
就得把 `{拿到钥匙}` 抄五遍 —— 抄漏一条就是一个走得进去的错误分支。

```
$若 拿到钥匙
- 开门 -> 密室
- 敲三下 -> 暗号
$否则
- 只能绕路 -> 后门
$结束
```

块里的选项、跳转、赋值都继承块的条件，可以嵌套。
`$否则` 取整个前置条件链的反。
体检和结局模拟都认这套 —— **不认的话，块里那些分支会被算成永远可达**，
比不做还糟。

### 14.3 从任意节点试玩（已实现）

「试玩」页签。选一个节点当起点，往后走一遍，看还能到哪些结局。

还能填一行「假设这些已经成立」：`好感度=3 拿到钥匙=真`。
试玩中段剧情**必须能假设「已经拿到钥匙了」**，
否则条件分支一条都走不进去，试玩出来的结果是假的。

写到第八章时想试「从这儿往后还能到哪些结局」，
每次都从头走一遍是没法用的 —— 这个页签就是为这件事做的。

### 14.4 导出给引擎（已实现）

「试玩」页签底下两个按钮：Ren'Py 和 ink。

| 引擎 | 怎么导 |
|---|---|
| **Ren'Py** | 一个节点一个 `label`，选项导成 `menu:`，跳转 `jump`，赋值 `$`，条件挂在选项上 |
| **ink** | 一个节点一个 `=== knot ===`，选项 `+`，条件 `{ }`，变量 `VAR` |

**Ren'Py 可以直接用中文标识符**（Python 3），所以节点名原样保留；
**ink 不行** —— 中文剥掉会变成空字符串，导出 `VAR  = 0`，既不报错也不能用。
所以 ink 的节点名和变量名全部换成 `n1` / `v1`，
并在文件开头留一张**中英对照表**。不留的话作者打开一看全是 n1 n2，
根本认不出哪个是哪个。

> ⚠️ **导出的是骨架，不是能跑的游戏。**
> 节点、选项、跳转、变量、条件都在；立绘、音乐、转场、界面不在 ——
> 那些本来也不在剧本里。这句话写在**按钮旁边**，不是只写在文件头里：
> 让作者以为导出来就能跑，他会拿去开工程，然后发现少一半东西。

导不过去的东西（布尔量声明成 0、没有出口的节点接了 `-> END`、
`角色: 台词` 在 ink 里会当成普通文本）都在界面上逐条列出来，不装作没事。

### 还没做的

- [ ] 导出到 Twine / Articy
- [ ] 试玩时手动一步步走（现在是一次跑完）

## 15. 从别的软件搬家（已实现）

「导入 / 导出」浮层里的第三个页签「从别的软件搬家」。

### 两条有把握的路

| 来源 | 怎么做 |
|---|---|
| **Scrivener** | 选那个 `.scriv` 文件夹。读 `*.scrivx` 的目录树，正文从 `Files/Data/<UUID>/content.rtf` 或 `Files/Docs/<id>.rtf` 取，RTF 扒成纯文本 |
| **一整个文件夹的 txt / md** | 按文件名里的**数字**排序，子文件夹算分卷。几乎所有软件都能导出成这个 |

只取 Scrivener 的 `DraftFolder` 那一支 —— Research、Trash 里的不是正文，
一股脑导进来只会把作者的目录搅乱。

**排序按数字比而不是按字符串比**：按字符串排的话「10」会排在「9」前面，
整本书的顺序就废了。

**必须走编码检测**：国内的 txt 很多是 GBK，当成 UTF-8 读进来就是一整本乱码，
而且看着像导入成功了。

### 青茉 / 码字精灵：暂时不做，并且说清楚为什么

它们的文件格式是私有的，**手上没有样本文件就不猜**。
猜错的后果是把作者几百万字导成乱码，而且看着还像成功了 ——
含糊其辞地「支持」一个没验过的格式，比明说不支持糟糕得多。

界面上直接写出来，并给出可行的替代路线：
在那边先导出成 txt（一章一个文件放进一个文件夹），
再用「一整个文件夹」导进来。

拿到真实工程文件之后，再按真实结构写。

## 5.4 伏笔连线（已实现）

伏笔面板的「连线」页签 —— 作者当初的原话是
「希望在大纲列表可以看到伏笔连线……或许做个开关最好？」，
做成一个页签就是那个开关。

左边是章节名（从上往下就是全书顺序），右边每条伏笔一条竖线：
从**埋**的那一章拉到**收**的那一章。

| 画法 | 意思 |
|---|---|
| 实心方块 | 埋点 |
| 空心圆 | 回收点 |
| **虚线拖到底** | 还没收 |
| 强调色 | 重要伏笔 |
| 红色 | **已经过了计划回收的章还没收** |

互不重叠的伏笔共用一条泳道（贪心分配），重叠的分开 ——
几十条叠在一起会糊成一片，而且会把两条线看成一条。

没收的那些不能不画，要画成虚线一直拖到最后一章：
**拖得越长越扎眼，这正是目的** —— 埋了八十章还没收的那几条，
本来就该一眼看见。

## 8.5 码字计划（已实现）

功能栏「码字计划」。三个页签：今天 / 目标 / 里程碑。

### 目标线：两条，都可自定义

作者原话：「不仅要有底线和理想线，这两条线也要可以自定义。」

| 线 | 含义 |
|---|---|
| **底线** | 写够就算达标、签到、接上连续天数 |
| **理想线** | 写够了这天算「很棒」，热力图上更深一档 |

**工作日 / 休息日分开填。** 底下存的是**一周七天的数组**（周一到周日），
界面上按「工作日 / 休息日」填四个数 —— 绝大多数人是这个模式，
但格式留着七天的自由度（有人周末才是主力写作时间）。

档位只是帮作者少打几个字，选完每个数都还能改：

| 档位 | 工作日 | 休息日 |
|---|---|---|
| 职业 | 8000 / 12000 | 4000 / 8000 |
| 半职业 | 3000 / 5000 | 5000 / 8000 |
| 业余（默认） | 1000 / 2000 | 2000 / 4000 |
| 随缘 | 0 —— 只记录，不判达标也不算断更 |

> 默认给业余档。**开箱不该甩给作者一个职业写手的数字。**

### ⭐ 改了目标，以前的日子按当时的目标算

这是整个模块存在的理由。

作者今天把目标从 3000 调到 8000，昨天写的 4000 还算不算达标？**算**。
所以目标存的是一份**变更历史**，每条带生效日期，
每天用那天生效的那条判定。

不这么做的话，调一次目标，整张热力图和连续天数当场全变 ——
那是在骗自己，而这个软件的名字就叫「不咕」。

界面上也把这句话写出来了：改目标时明说「从今天起生效，以前的日子仍按当时的目标判」——
不写的话，作者调完看见热力图没变会以为坏了。

### 补签线跟着目标走

**按倍数，不按绝对字数**：写够底线的 2 倍挣 1 次补签额度。

写死一个 10000 是不行的 —— 目标 1000 的人和目标 8000 的人，
「今天多写了一倍」的含义完全一样，绝对值却差八倍。

额度**只能往前补**，不能预支。给昨天的自己发好人卡没有意义。

### 请假：不断链，但留痕迹

标了请假的那天：连续天数不断，但**不算达标**。
热力图上画中性色 —— 不是绿也不是空白，一眼看得出那天没写。

请假日写了字也照记，仍看得出他其实写了。请假日不挣补签额度。

面板上会写明这段连续里有几天是补签的、几天是请假撑着的 ——
**「撑」出来的天数得让作者知道。**

### 统计口径：全库合计

目标是「人」的属性，不是「书」的属性。作者说「每天写 8000 字」，
指的是这一天总共写了多少，不分在写哪本 —— 所以判定用的是
**所有作品当日字数的合计**。

### 存在哪

`<库根>/_计划.yaml`，可读的 YAML，**跟着坚果云同步走** ——
换台电脑目标不用重设。带注释头，作者拿记事本也能改。

文件坏了、字段缺了都退回空计划而不是抛错：
一个 YAML 打错字不该让作者连字数统计都打不开。

## 8.6 里程碑（已实现）

作者原话：「更多是写作完毕〈大纲-人物〉、写作完毕〈第一卷〉等等。」

所以里程碑首先是**盯住一个具体对象**：

| 盯住什么 | 进度怎么算 |
|---|---|
| **某一卷** | 卷里写了内容的文档 / 总文档 |
| **某个设定分类**（如「大纲-人物」） | 同上 |
| 某一篇 | 写了没写 |
| 字数目标 | 全书字数 / 目标 |
| 章节数目标 | 章节数 / 目标 |
| 自由事项 | 完没完作者自己勾 |

每条可以带截止日。带了就会算：

- 还剩几天 / 逾期几天
- **每天还得写多少**（剩余量 ÷ 剩余可写天数，**已排的请假日除外**）
- 按最近 14 天的日均速度，**会晚几天**

> 「会晚几天」**只在会晚的时候说**。早到不邀功 —— 提醒的价值在于坏消息。

排序：逾期 → 快到期 → 有截止日 → 没截止日 → 已完成。
**完成的沉到底**，它们不需要作者再看一眼。

**手动标完成优先于自动算出来的进度。** 作者说完了就是完了。

算不出总量时百分比是 **null 而不是 0** —— 0% 会让人以为一点没做，
而真相是「这个目标没法自动算进度」。

存在 `<作品>/.bugu/milestones.jsonl`，仅追加、同 id 后写覆盖，
跟伏笔一个套路，多设备改了能合。

### AI 协助：还没做，而且不是必需

「这一卷大概还要多少字」这类要读正文才知道的判断，AI 有价值。
但「还剩几天、每天要写多少、会不会晚」**纯算术就够**，
现在这些都不依赖 AI，也不会因为没填 API Key 就少一块功能。
