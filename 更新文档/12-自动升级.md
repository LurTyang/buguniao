# 12 · 自动升级

> **状态：已实现（随 1.0「被遗忘的旋律」一起发）。**

## 0. 这件事的形状

服务器上摆一份几 KB 的清单 `latest.json`，软件**启动时读它一次**，
比一下版本号。有新的就在书架上挂一条横幅。

```
软件                       host
 │   启动时 GET latest.json  │
 ├──────────────────────────>│   几 KB
 │<──────────────────────────┤
 │ 比版本号（shared/update.ts）
 │ 有新的 → 书架上挂一条
 │
 │ 作者点「下载」            │
 ├──────────────────────────>│   100 MB
 │<──────────────────────────┤   边下边算 SHA-256
 │ 对得上 → 作者点「装上」→ 静默跑安装程序、装完自己起来
 │ 对不上 → 删掉，把两串哈希都摆给他看
```

## 1. 三条定死的规矩

### 1.1 启动时只查一次，查不通一声不响

查的是几 KB 的 JSON。没网、服务器挂了、代理没开、域名没了 ——
**处理方式全都一样：当作没有新版本。** 一个装饰性的检查不该有能力
打扰正在写字的人，更不该有能力拦住启动。

设置里能整个关掉（`updateCheck`）。有人不想让软件联网，那是他的自由。

### 1.2 不自动下载、不自动重启

**「自动」只体现在「查」这一步。** 下载 100MB 要作者点一下，安装再点一下。

理由跟铁律四同源：软件在你写字的时候偷偷占带宽，甚至自己重启 ——
那会毁掉正在进行的一坐。而「有新版本」这件事，一点也不急。

### 1.3 装之前一定核对 SHA-256

这软件**没有代码签名证书**。那串哈希是唯一能证明「这个包是作者发的」
的东西（发布清单里一直记着它，见 `release/历史版本/README.md`）。

- 边下边算，不是下完再读一遍
- 对不上：删掉那个文件，**把期待值和实得值都摆给作者看**。
  对不上有两种可能 —— 下载被截断了（重试就好），或者这个包不是作者发的。
  后一种是安全事故，作者的读者有权知道到底发生了什么。
- 清单里的下载地址**必须是 https**，`sha256` 必须是 64 位十六进制。
  差一样就当这份清单不存在（`shared/update.ts` 的 `parseManifest`）。

## 2. 下载地址写在清单里，不写在软件里

这一条是有意的，也是整件事里最值钱的一个决定：

> **哪天换 host，改那份清单就行。**

已经装在别人机器上的软件会跟着换过去，不用为了换个下载地址再发一版。
所以「用哪个网盘 / 哪台服务器」不是代码决定，是部署决定：

| host | 好处 | 代价 |
|---|---|---|
| **作者自己那台**（`bugu.char46.top`，跟对外统计同一个域名） | 已经在跑了、地址稳、自己说了算 | 100MB × 下载次数的流量走自己的带宽 |
| **GitHub Releases** | 不花钱、不占自己带宽、地址稳 | 国内可能慢 |
| 对象存储（OSS / COS / 七牛） | 国内快、按量便宜 | 要开账号、要记一笔账 |
| 网盘（坚果云 / 百度 / 阿里） | 现成 | **多数给不了稳定的直链**：分享链接是一张网页、会过期、会限速；而 WebDAV 要账号密码 —— 把账号密码塞进客户端，等于把自己的网盘交出去 |

**建议：清单放自己那台**（它一定活着，而且几 KB 的东西不占什么），
**包放哪儿都行**，清单里指过去。软件只硬编码清单那一个地址
（`updateUrl`，设置里也能改 —— 万一连域名都得换，作者还能自救）。

### Caddy 加一段就能发包

```
bugu.char46.top {
	# 升级清单和安装包：静态文件，交给 Caddy 直接发，不经过统计服务
	handle_path /dl/* {
		root * /srv/bugu-dl
		file_server
	}
	reverse_proxy 127.0.0.1:8787
}
```

然后把 `release/` 里那三样（两个 exe + `latest.json`）传到 `/srv/bugu-dl/`。

## 3. 清单长什么样

`pnpm release` 自己生成（`scripts/release.mjs`），不用手写：

```json
{
  "version": "1.0.0",
  "name": "被遗忘的旋律",
  "date": "2026-09-28",
  "notes": "这一版主要是外观。功能没怎么加，改的是「东西摆在哪儿、找不找得到」。",
  "page": "https://github.com/LurTyang/buguniao/releases/tag/v1.0.0",
  "setup":    { "url": "https://…/buguniao-setup-1.0.0.exe", "size": 104748577, "sha256": "78e7…" },
  "portable": { "url": "https://…/buguniao-1.0.0-win-x64.exe", "size": 104563659, "sha256": "313a…" }
}
```

- **版本名和那句话从更新日志里读** —— 一处写、一处用。
  日志顶上那条跟 `package.json` 对不上时只警告，不阻断打包
  （这时候拦下来，只会让人去改脚本，而不是去写日志）。
- 地址前缀：`BUGU_DL_BASE=https://某处/dl/ pnpm release`，不写就用默认那台。

## 4. 免安装版装不了自己

正在跑的那个 exe 没法被替换掉。所以免安装版只把新包下下来、
**在资源管理器里指给作者看**，让他自己换。

假装能自动升级、然后失败在一个说不清的地方，比老老实实说
「你自己换一下」更糟。

（安装版走的是 electron-builder 那个 NSIS 包认的
`/S --force-run`：静默装、装完自己起来。）

## 5. 隐私

检查更新会向 host 发一个 GET，对方能看见 IP 和 User-Agent，
**不带任何身份信息、不带版本号以外的东西**（版本号在 URL 里没有，
比较是在本地做的 —— 下载的是同一份清单，谁都一样）。

设置 → 升级里能整个关掉。
