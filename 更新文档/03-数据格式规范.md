### 1.1 文件名排序规则

同一目录内**按文件名字典序排序**，这样在资源管理器里看到的顺序也是正确的顺序。

序号使用**四位间隔编号**：`0010-`、`0020-`、`0030-`……

> **为什么间隔 10：** 在第一章和第二章之间插入新章时，用 `0015-` 即可，
> 只需重命名 1 个文件，而不是把后面 300 章全部重编号（那会造成大量同步流量）。
> 间隔用完时（连插 9 章）才触发一次整段重排，并提示用户。

**排序序号是文件名的一部分，不是元数据。** 拖拽排序 = 重命名文件。

## 3. 文档 front-matter

每个 `.md` 文件顶部使用 YAML front-matter：

```markdown
---
id: ch-a1b2c3
type: chapter
title: 第一章 坠楼
created: 2026-08-25T10:00:00+08:00
updated: 2026-08-25T14:30:00+08:00
status: draft
---

正文从这里开始……
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | 是 | **稳定不变的唯一标识**。版本历史、伏笔、统计全部靠它关联。文件改名、移动都不影响 |
| `type` | 是 | `chapter` 正文 / `outline` 大纲 / `setting` 设定集 / `idea` 灵感 / `script` 剧本（二期） |
| `title` | 是 | 显示用标题。与文件名可以不一致，以此字段为准 |
| `created` / `updated` | 是 | ISO 8601 带时区 |
| `status` | 否 | `draft` 草稿 / `done` 完成 / `revising` 修订中 |

### id 生成规则

`{类型前缀}-{6位base36随机}`，如 `ch-a1b2c3`、`set-x9k2m1`、`out-p3q7r5`。

**若打开一个没有 `id` 的 `.md` 文件**（比如用户手动新建的、或从别处拷进来的），
软件自动补写一个 id 并保存。这保证了「用记事本随手加一章」也能被正常纳管。

## 4. 便利贴 `@` 语法（核心特性）

### 4.1 作用域

**`@` 语法仅在 `type: setting` 的文档中生效。**

正文（`chapter`）、大纲（`outline`）、灵感（`idea`）中的 `@` **永远是普通字符**，
不做任何解析。这样写邮箱、写对话「@某人」都不会误触发。

### 4.2 卡片标题

一个设定集文档 = 一张便利贴。标题按以下顺序取第一个命中的：

1. 文档中**第一个 `#`（一级标题）** 的内容
2. 若无 `#`，取文档中**出现的最高级别标题**的第一个（如全是 `##`，则取第一个 `##`）
3. 若无任何标题，取**文件名**（去掉 `.md`）

### 4.3 浮出规则

「浮出」= 该内容显示在便利贴**卡片正面**。未浮出的内容需要点开卡片才能看到。

**先定义：** 「**独占行 `@`**」指该行去掉首尾空白后**恰好等于 `@``。

逐行扫描，按下表**从上到下**判定，命中即停：

| 规则 | 条件 | 行为 |
|---|---|---|
| **A · 块标记** | 该行是独占行 `@` | 从下一行起、到下一个独占行 `@` 之前（不含两个 `@` 行本身）的所有内容整块浮出。若直到文末都没有配对的独占行 `@`，则浮出到文末 |
| **B · 整行标记** | 该行以 `@` 开头，**且未转义 `@` 恰好一个** | 整行浮出（浮出内容不含开头的 `@`） |
| **C · 行内标记** | 未转义 `@` 的个数为**不小于 2 的偶数** | 第 1↔2 个 `@` 之间、第 3↔4 个之间……依次浮出 |
| **D · 不触发** | 其余情况 | `@` 视为普通字符 |

**关键判定速查：**

| 写法 | @ 数 | 规则 | 结果 |
|---|---|---|---|
| `@表面身份：城南药铺学徒` | 1（行首） | B | 整行浮出 |
| `年龄：@十七岁@，实为三百余岁` | 2 | C | 浮出「十七岁」 |
| `@十七岁@，实为三百余岁` | 2 | C | 浮出「十七岁」（**不是**整行） |
| `lisi@qq.com` | 1（非行首） | D | 普通字符 |
| `@甲@乙@` | 3 | D | **不触发** |

> **「恰好一个」这个条件由作者于 2026-08-25 定稿：**
> 「仅一个的时候，考虑整行浮出。三个或五个，也不会整行浮出。」
>
> 三个、五个 `@` 通常是手误（少打或多打了一个）。不触发比猜错强 ——
> 编辑器会在这类行旁边给出提示（`lintFloats()`），告诉作者「这行有 3 个 @，
> 无法两两配对，不会浮出」，但**不自动修改**。
>
> 实现与测试见 `app/packages/core/src/sticky/`（64 个测试）。

### 4.4 补充规则

- **转义：** `\@` 表示字面量 `@`，不参与任何判定
- **代码块内不解析：** 被 ` ``` ` 围栏包裹的内容中的 `@` 一律视为普通字符
- **块区域内不再二次解析：** 规则 A 圈定的区域内，`@` 不再按 B/C 处理，整块原样浮出
- **浮出顺序：** 按在文档中出现的先后顺序拼接。块保留原有换行；行内浮出各占一行

### 4.5 示例

```markdown
---
id: set-x9k2m1
type: setting
title: 李四
---

# 李四

年龄：@十七岁@，实为三百余岁。          ← 规则C，浮出「十七岁」

@表面身份：城南药铺学徒                  ← 规则B，整行浮出

@                                       ← 规则A 起
外貌：断眉，左手常年缠布
惯用兵器：一把无锋的短刀
@                                       ← 规则A 止（中间两行整块浮出）

（下面是不浮出的详细背景）
李四本名不叫李四，他真正的姓氏……
联系方式记在这里 lisi@qq.com            ← 规则D，不触发，@ 是普通字符
价格 10\@斤                             ← 转义，字面量 @
```

**渲染出的便利贴卡片正面：**
```
┌─ 李四 ─────────────────┐
│ 十七岁                  │
│ 表面身份：城南药铺学徒    │
│ 外貌：断眉，左手常年缠布  │
│ 惯用兵器：一把无锋的短刀  │
└────────────────────────┘
```

### 4.6 双向链接

设定集与正文中均支持 `[[李四]]` 语法：
- 匹配规则：先按**便利贴标题**精确匹配，再按**文件名**匹配
- 在正文中，`[[李四]]` 在编辑器里渲染为可点击的高亮文本，**但保存到文件时保留 `[[]]` 原样**
- 支持别名：`[[李四|那个断眉少年]]`，显示后者，链接指向前者
- 未匹配到的链接显示为灰色（表示「还没建这张便利贴」），点击可一键创建

## 5. 伏笔标记

### 5.1 正文中的锚点

伏笔在正文里用**成对 HTML 注释**包裹。Markdown 渲染时不可见，记事本打开也能看懂：

```markdown
他下意识摸了摸胸口，<!--埋#f7k2p9x-->那块温润的玉佩还在<!--/埋#f7k2p9x-->。
```

回收时：

```markdown
<!--收#f7k2p9x-->玉佩碎成两半，露出里面刻的半个「沈」字。<!--/收#f7k2p9x-->
```

| 标记 | 含义 |
|---|---|
| `<!--埋#{id}-->` … `<!--/埋#{id}-->` | 埋设点 |
| `<!--收#{id}-->` … `<!--/收#{id}-->` | 回收点 |

- id 格式：`f` + 6 位 base36（如 `f7k2p9x`），共 7 字符
- 开闭标记都带 id，因此**允许嵌套和交叉**
- 一个伏笔可以有**多个回收点**（分批回收）
- 若只在清单里记录、还没写到正文，则正文中**没有**任何标记，仅在元数据中存在

> **为什么用注释而不是独立的坐标文件：** 独立坐标文件会在正文被编辑后失效（锚点漂移）。
> 注释是内嵌的，你怎么改文本它都跟着走，而且用记事本打开也一目了然。

### 5.2 伏笔元数据

`.bugu/foreshadow/{deviceId}.jsonl` —— **每行一条 JSON，仅追加，同 id 后写覆盖先写**。

```json
{"schemaVersion":1,"id":"f7k2p9x","ts":1756100000,"dev":"pc-01","title":"沈家玉佩","desc":"主角贴身戴的玉佩，实为沈家信物","plantedIn":"ch-a1b2c3","expectBy":"第三卷","status":"planted","priority":"high"}
{"schemaVersion":1,"id":"f7k2p9x","ts":1756200000,"dev":"pc-01","status":"recovered","recoveredIn":["ch-m4n8q2"]}
```

| 字段 | 说明 |
|---|---|
| `id` | 伏笔 id，与正文注释中的 id 对应 |
| `title` | 短标题，清单里显示 |
| `desc` | 伏笔内容描述（作者自己写的备忘） |
| `plantedIn` | 埋设所在文档 id；未写入正文时为 `null` |
| `expectBy` | 大致回收时间。可以是自由文本（「第三卷」）或文档 id |
| `status` | `planned` 只记未写 / `planted` 已埋 / `recovered` 已收 / `abandoned` 放弃 |
| `priority` | `high` / `normal` / `low`，影响清单排序和提醒强度 |

> **为什么用「仅追加 + 后写覆盖」而不是直接改 JSON：**
> 追加写永远不会产生冲突（两台设备各写各的分片文件），
> 而重写整个 JSON 文件在多设备场景下会互相覆盖。
> 读取时把所有 `{deviceId}.jsonl` 合并，按 `ts` 排序，同 id 取最新。

## 6. 版本历史

`.bugu/history/{docId}/{deviceId}.jsonl` —— 每个文档一个目录，每台设备一个分片文件。

```json
{"schemaVersion":1,"v":1,"ts":1756100000,"dev":"pc-01","kind":"snapshot","chars":0,"data":""}
{"schemaVersion":1,"v":2,"ts":1756100120,"dev":"pc-01","kind":"patch","chars":842,"data":"@@ -1 +1,3 @@\n+他从四十八楼掉下去的时候……\n"}
{"schemaVersion":1,"v":3,"ts":1756100400,"dev":"pc-01","kind":"patch","chars":1503,"label":"写完开头","data":"@@ ..."}
```

| 字段 | 说明 |
|---|---|
| `v` | 版本号，单调递增 |
| `kind` | `patch` 增量 / `snapshot` 全量快照 |
| `data` | patch 为 unified diff 文本；snapshot 为全文 |
| `chars` | 该版本的总字数（统计模块直接用，不用重算） |
| `label` | 手动打的命名标记，如「完成第一卷」。无标记时省略此字段 |

**快照策略：每 50 个 patch 存一次 snapshot。** 这样恢复任意版本最多应用 50 次 patch。

**容量管理：**
- 扫描 `.bugu/history/` 总大小，与 `book.yaml` 的 `historyLimitMB` 比较
- 达到 80% 时黄色提示，达到 100% 时红色横幅并暂停写新历史（**不静默丢弃**）
- 清理界面提供：按时间段删除、只保留带 `label` 的版本、提高上限 三个选项

## 7. 统计数据

`.bugu/stats/{deviceId}.jsonl` —— 仅追加。

```json
{"schemaVersion":1,"ts":1756100120,"dev":"pc-01","doc":"ch-a1b2c3","delta":842,"total":842,"session":"s-3k9","pomo":true}
```

| 字段 | 说明 |
|---|---|
| `delta` | 本次保存相对上次的**净增字数**（可为负） |
| `total` | 该文档保存后的总字数 |
| `session` | 写作会话 id，连续写作（间隔 < 30 分钟）算同一会话 |
| `pomo` | 该次保存是否发生在番茄钟运行期间 |

日/周/月曲线和年度热力图全部由这些记录聚合得出。

## 8. 便利贴悬浮布局

`.bugu/workspace/{deviceId}.json` —— 每台设备各自的桌面布局，互不干扰。

```json
{
  "schemaVersion": 1,
  "pinned": [
    { "cardId": "set-x9k2m1", "x": 420, "y": 180, "w": 260, "h": 320,
      "collapsed": false, "scope": "book" },
    { "cardId": "set-p3q7r5", "x": 700, "y": 240, "w": 260, "h": 200,
      "collapsed": true, "scope": "doc:ch-a1b2c3" }
  ]
}
```

`scope` 决定这张便利贴在哪里显示：
- `"book"` —— 全书任何章节都悬浮显示（适合主角设定）
- `"doc:{docId}"` —— 只在指定文档编辑时显示（适合本章才出场的配角）

## 9. 灵感碎片

文件名：`{YYYYMMDD}-{HHmmss}-{设备标识}.md`，例如 `20260825-143012-phone.md`。

```markdown
---
id: idea-k8m3p1
type: idea
title: 反派的动机可以是……
created: 2026-08-25T14:30:12+08:00
source: mobile
---

反派其实不想赢，他想输给主角，因为只有输了他才能……
```

**「只增不改」的落实点在这里：** 手机端每记一条就新建一个文件，
文件名带时间戳到秒 + 设备标识，**两台设备不可能生成同名文件**，因此同步永不冲突。

桌面端可以把灵感碎片「归入」某章或某设定 —— 归入操作是
「读取内容 → 追加到目标文件 → 删除碎片文件」，仍不违反任何原则。

## 文档 front-matter 里的 `device`

```yaml
---
id: ch-xxxxx
type: chapter
title: 第一章
created: 2026-08-26T10:00:00.000+08:00
updated: 2026-08-27T01:40:00.000+08:00
device: 书房台式机          # 最后一次是在哪台机器上改的
---
```

给「这一篇在别处也改过」那个对话框用的 —— 只说「另一台设备」等于没说，
作者得看见是「书房台式机」还是「公司笔记本」才决定得了要哪一版。

设备名默认取主机名，存在本机配置里（`deviceName`），不跟着同步走；
写进文档的只是**当时那台机器的名字**。
老文档没有这一项，界面上显示「不知道是哪台」。

## book.yaml 里的作品类型与人物分类

```yaml
kind: script          # novel（默认，可不写） / script / game
castFrom:             # 设定集里哪几个分类算「人物」，可多选
  - 人物
  - 配角
pinned: true          # 置顶。取消后这一行就没了，不留 false
```

`kind` 决定新建时套哪份骨架、界面默认按哪套格式排。
**只在书架页右键改** —— 换类型会换掉整本书的排版规矩。
老书没有这一项，按小说算。

`pinned` 存在书自己的 `book.yaml` 里而不是一份全局清单 ——
换台电脑、或者把某本书单独拷走，置顶都跟着走，
也不会留下一条指向不存在的书的记录。

`castFrom` 空数组和「没有这一项」是**两件事**：
空数组是作者选了「一个分类都不算人物」，没有这一项是他还没选过
（那时候按分类名猜，猜「人物 / 角色 / 人设」这些）。
所以空数组也要写出来。

## 剧本格式

一期已实现。规矩只有一条：**不发明新符号**。

铁律第一条是「文件即真相」—— 剧本也得是记事本打开就能读的纯文本。
所以只认中文剧本本来就在用的写法：

```markdown
# 第一场　内景·咖啡馆·日

（李四推门进来，雨水顺着伞尖滴在地板上。）

李四：你等很久了？
王五（头也不抬）：还好。

（长久的沉默。王五把杯子推过去。）
```

也就是说，**一个剧本文件用别的软件打开、直接打印出来，仍然是一份剧本**。
软件做的只是把它认出来：对齐排版、数台词量、按场跳转。

### 认行的规矩

按顺序判，先中先算：

| 顺序 | 形态 | 认成 |
|---|---|---|
| 1 | `#` 开头 | 场景标题 |
| 2 | 整行被 `（）` 或 `()` 裹住 | 动作 / 舞台指示 |
| 3 | `角色名：台词`，角色名后可带 `（表演提示）` | 台词 |
| 4 | 其余 | 叙述 |

第 3 条最容易误伤，所以卡得很死：

- 角色名**不超过 10 个字**
- 角色名里**不能有标点或空白**
- 角色名**不能以 `@ < > * | # -` 这些开头** ——
  那些是便利贴浮出、伏笔锚点、Markdown 的地盘。
  `@身份：庄主` 被排成一句台词，是这个解析器最容易犯的错

所以「他抬起头，看着窗外：雨停了。」不会被当成台词。
台词里再出现冒号也不会二次切分（`李四：他说：走吧` 的台词是「他说：走吧」）。

### 角色名从设定集来

`角色名：台词` 靠正则是猜的，挡不掉「时间：三年后」。
所以再读一份**确凿的名单**：`book.yaml` 的 `castFrom` 指的那几个
设定集分类，里面每张卡的名字就是角色名。

| 从哪儿取 | 写法 |
|---|---|
| 卡片名 | `李四.md`。`01-李四（男主）.md` 也认，编号和括号会去掉 |
| 别名行 | 卡片正文里 `别名：小李、李哥`。`又名 / 绰号 / 小名 / 称呼` 都认 |

带标点的、超过十个字的名字不收 —— 那不是名字，
是作者拿卡片名写了一句话。

**统计仍然按写在纸上的名字算**，不把「小李」偷偷并进「李四」：
显示什么就统计什么，偷偷归并会让作者对不上数。

### 剧本排版只改显示

打开「剧本排版」开关后，编辑器按层次缩进（场景顶格、动作缩两格偏灰、
台词缩四格），**认得出来的角色**还会把名字单独排一行：

```
    李四
      你等很久了？
```

名字缩四格、台词缩六格，冒号藏起来（光标停在这一行时不藏 ——
正在改的那行如果字符会凭空消失，退格删到哪儿全靠猜）。

但**文件里一个字节都不会变** —— 拆行靠的是 CSS 的 `display:block`，
一个块级元素后面的文字自然落到下一行。关掉就是原来的纯文本，
这一条在界面上明写，并且有测试盯着。

剧本书（`kind: script`）默认开着这个开关。

## 游戏剧本格式

在剧本格式之上只加**四样东西**：节点、选项、跳转、变量。

```markdown
# 初见

（教室后排，窗外是操场。）

李四：你是新来的？

- 点头 -> 承认
- {好感度>=3} 搭话 -> 熟络

# 承认

$ 好感度 += 1

李四：我叫李四。

-> 放学
-> 【结束】
```

| 写法 | 意思 |
|---|---|
| `# 节点名` | 一个节点。**标题文字就是它的名字**，跳转按这个名字找 |
| `- 选项文字 -> 目标` | 一个选项 |
| `- {条件} 选项文字 -> 目标` | 带条件的选项 |
| `-> 目标` | 直接跳过去（独占一行） |
| `-> 甲、乙、丙` | 一行列多个去处，**每个自动成为一个选项**，选项文字就是节点名 |
| `<- 甲、乙` | 合并：那几个节点都流到**当前这个**节点来 |
| `-> 【结束】` | 结局。方括号里写什么都是结局名 |
| `-> ↩ 节点名` | 有意绕回前面出现过的节点 |
| `-> 结束` | 结局（兜底写法）。保留名还有 `完`、`结局`、`END` |
| `$ 变量 = 值` / `$ 变量 += 数` | 变量操作 |

### 结局要写成 `【…】`（0.3 加的）

`-> 结束` 这种保留名有个坑：**书里真有一个节点叫「结束」的时候，
整条线会在跳过来的那一刻被当成结局掐掉**，而作者只会看到
「我后面写的都走不到」。给节点起名叫「结束」是他的自由。

所以规矩改成两条：

- `【…】` 里的名字**永远**是结局，跟任何节点名都撞不上
- 保留名只是兜底：`-> 结束` 只在**书里没有同名节点**时才当结局，
  有同名节点就是跳过去

老稿子不受影响 —— 没有叫「结束」的节点时，`-> 结束` 还是结局。

### 回绕要标 `↩`（0.3 加的）

跳到一个**前面已经出现过**的节点，而且没写 `↩`，体检会提一句
「绕回去了」。**这是提示，不是错**：有意的循环（回到选择菜单、
重复的日常）当然合法，标一个 `↩` 就不提了。

它防的是另一种：两段不相干的剧情不小心起了同一个名字，于是后面那段的
跳转悄悄绕回了前面 —— 图上看着还挺正常，而作者会以为新写的分支走不到。

### 合并：`<- 甲、乙`（0.3 加的）

「分歧一下、之后故事线还是同一条」是分支剧情里最常见的形状。
原来写它要跑去**每一个**分支节点尾巴上补一行 `-> 放学`：
五条分支五个地方，加一条分支还得记得回来补第六个，漏一个就是一条死路 ——
而死路是要走到才发现的。

现在在合流的那个节点上写一行就够，**它自己声明谁流进来**：

```markdown
# 承认

嗯。

# 冷场

沉默。

# 放学

<- 承认、冷场

（铃响了。）
```

规矩：

- 被点名的节点**自己没写出口**时，才给它补一条通向这里的隐式出口
- 它自己写了出口就听它的，并且体检报一条「合并没生效」——
  合并声明不该悄悄改掉已经写明白的走向
- 点名了一个不存在的节点，按断头路报

### 一行多个去处：`-> 甲、乙、丙`（0.3 加的）

「这个时间段去哪儿」这种自由度高的写法，原来得一条一条抄：

```markdown
- 图书馆 -> 图书馆
- 天台 -> 天台
- 社团 -> 社团
```

目标和选项文字是同一个词，抄一遍纯属浪费，抄错一个字就是断头路。现在：

```markdown
-> 图书馆、天台、社团
```

展开出来的每个选项，**文字就是它的节点名**。顿号、逗号、斜杠都能当分隔符。

只有**直接跳转**那一行才拆 —— `- 点头 -> 甲、乙` 拆完两个选项都叫「点头」，
那不是作者要的，所以它不拆。

### 为什么是 `$` 和 `{}`

`@` 是便利贴浮出、`<!--` 是伏笔锚点、`[[]]` 是双链、`#` 是节点、
`（）` 是动作 —— 全占了。`$` 和 `{}` 是仅剩的干净符号，
而且 `$` 在游戏脚本里本来就是「设变量」的惯例写法。

### 条件

`变量 运算符 值`，运算符支持 `> < >= <= == != =`。
值可以是数字、`真/假`、或一段文字。另外两种简写：

- `{拿到钥匙}` —— 这个变量是真的
- `{非 拿到钥匙}` —— 取反

**没赋过值的变量，拿数字比时当 0。**
这一条很重要：`{好感度<1}` 在一次都没加过好感度时必须成立 ——
不然「冷淡线」会被判成永远走不到，而它恰恰是默认路线。

条件**认不出来时不猜**，界面报「条件写坏了」。
猜成真或假，作者就会以为某条分支永远走不到。

### 块级条件

一段里好几条选项要同一个条件时，把 `{拿到钥匙}` 抄五遍太容易抄漏一条 ——
漏一条就是一个走得进去的错误分支。所以另给一套块写法：

```markdown
$若 拿到钥匙
- 开门 -> 密室
- 敲三下 -> 暗号
$否则
- 只能绕路 -> 后门
$结束
```

| 写法 | 别名 |
|---|---|
| `$若 条件` | `$如果`、`$if` |
| `$否则` | `$else` |
| `$结束块` | `$结束`、`$end` |

块里的选项、跳转、赋值都继承块的条件，可以嵌套（内层是「且」）。
`$否则` 取整个前置条件链的反。

**体检和结局模拟都认这套。**
不认的话，块里那些分支会被算成永远可达 —— 比不做这个功能还糟。

> `$结束` 既是块结束又像结局保留名，但两者位置不同：
> 结局是 `-> 结束`（跳转的目标），块结束是行首 `$`。互不干扰。

### 跳转跨文件

整本书的正文一起建图。游戏剧本一个节点一个文件、或者一章多个节点都很常见，
跳不出文件就没法写大型分支。代价是要把所有正文读一遍
（目录树那层刻意不读内容，这里只好自己读）。

**同名节点是致命错误** —— 跳转不知道该去哪一个，所以两处都会被报出来。

### 导出给引擎

能导成 Ren'Py（`script.rpy`）和 ink（`script.ink`）。

**Ren'Py 直接吃中文标识符**（Python 3），节点名原样保留。
**ink 不行** —— 它的 knot 名只认字母数字下划线，中文剥掉会剩空字符串，
导出 `VAR  = 0` 这种既不报错也不能用的东西。所以 ink 那一份把
节点名和变量名全换成 `n1` / `v1`，并在文件开头留一张中英对照表。

导出的是**骨架**：节点、选项、跳转、变量、条件。
立绘、音乐、转场、界面不在里面 —— 那些本来也不在剧本里。
