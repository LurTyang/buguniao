# 04 · 界面与交互设计

## 1. 设计基调

**默认极简，能力藏在边上。**

打开软件看到的应该是一张干净的稿纸，而不是一堆面板。
所有能力都在侧边栏里，鼠标靠过去才出现，需要常驻时可以钉住。

### 2.3 侧边栏行为规范

| 行为 | 规则 |
|---|---|
| **唤出** | 鼠标横坐标进入窗口左/右 **60px** 范围，延迟 **160ms** 后滑出 |
| **收起** | 鼠标离开侧边栏区域，延迟 **400ms** 后收起（防止移动过程中误收） |
| **钉住** | 点侧边栏右上角的图钉，常驻，正文区相应缩窄。**存进设置，跨重启** |
| **写作时自动收起** | 开始连续输入后立即收起未钉住的侧边栏（钉住的不受影响） |

> **触发方式在 2026-08-25 按实际使用反馈改过。**
>
> 初版是在边缘放一个 10px 宽的透明 div 当触发区，结果是「以为该触发但就是
> 触发不了」—— 10px 太窄，鼠标很难精准停上去。而且那个透明 div 会挡住
> 底下的点击，想点稿纸边缘反而点不到。
>
> 现在改成**监听整个写作区的鼠标位置**，横坐标进入左右 60px 就唤出。
> 既宽松得多，又完全不影响任何点击。

> **钉住状态要跨重启（0.3 修）。**
>
> 原来钉住只活在内存里，关掉软件再打开就散了。作者钉上它是因为
> 他要一直看着目录 —— 那是个决定，不是个手势。每次开软件都得重钉一遍，
> 等于这个功能没做。现在存在 `dirBarPinned` / `toolBarPinned` 里。

**左右互换**放在**设置**里，不在侧边栏上。
理由：这是个一次性的偏好（惯用手、屏幕摆放），不是每次进来都要重设的东西。
设置写进本机配置文件，不参与同步 —— 两台电脑的分辨率和习惯可能不一样。

### 2.3.1 哪些行顶格

正文默认缩两格（CSS 的 `text-indent`，**文件里不存全角空格**，见 05 §2）。
不吃这个缩进的是**标记行**：

| 顶格 | 是什么 |
|---|---|
| `# 标题` | 标题（`#` 后要有空格） |
| `> 引用`、`- 列表`、`1. 列表` | Markdown 的块级标记 |
| `---`、` ``` `、`~~~` | 分隔线、代码围栏 |
| `@这一行` | 整行浮到稿纸上。行首那个 `@` 还会上色 —— 它是标记，不是正文 |
| `<!--埋#…-->` | 伏笔锚点 |

理由是**一眼扫得出来**：缩两格的标记混在缩两格的正文里，
得逐行读才认得出哪行是标记。

> `@` 是 0.3 补上的 —— 原来 `#` 和 `<` 顶着格，`@` 却跟正文一样缩进，
> 看着像漏了（作者报过这个）。判定写在 `NO_INDENT_RE`，9 个测试钉着：
> 它错了不报任何错，只是某类标记看着不对，只能靠人眼在一屏字里发现。

### 2.3.2 写起来什么感觉（0.4）

四个开关，**全都只影响显示与输入的那一刻，不改文件里已有的字**。
放在外观设置里（写作页侧边栏、书架页设置弹窗，两处是同一个组件）。

| | 干什么 | 默认 |
|---|---|---|
| 打字机 · 竖向 | 当前**行**停在屏幕中部，往下写是纸在动、眼睛不动 | 关 |
| 打字机 · 横向 | 当前**列**停在水平中央，稿纸横着走 | 关 |
| 专注模式 | 当前段落之外的字变淡（只压透明度，不改颜色） | 关 |
| 智能替换 | 打 `"` 出中文弯引号、`--` → `——`、`...` → `……` | **开** |

**横向打字机跟自动折行是互斥的。** 折行时一行永远填不满、光标也就永远
走不到右边，横向根本没得动。所以打开它会关掉折行 ——
这件事要在开关下面写出来，不能默默改掉作者的排版。

**智能替换的三条不许破：**

1. 只在敲下那一刻替换，**绝不做全文扫描式的「修正」**（那会改到引用的原文、代码、外文）
2. **撤销一次退回原本打的那个字符** —— 做法是分两笔：先正常插入他打的字符，
   再单独发一笔替换。这一条比功能本身还重要，撤不回来人就不敢打字了
3. 一键全关

默认给的是**中文弯引号**而不是直角引号。直角引号是轻小说和港台排版的习惯，
不是大多数人写东西的样子（作者原话：「中文引号使用频率实则远高于直角引号」）。
直角引号留作可切换的一档，两者监听同一个键，所以**开一个会自动关掉另一个** ——
两个都开的话谁排在前面谁生效，用的人只会觉得「时灵时不灵」。

### 2.4 图标与简约

**整体设计以简约为主。** 具体到几条硬约束：

- 侧边栏的钉住**只有一个单色图钉图标**，没有文字、没有 emoji（参照 Word）
- 功能列表（字数统计、全文检索、伏笔……）**不带任何图标**，只有文字
- 界面里不出现 emoji

初版在功能列表里放了 📊🤖🍅🔍🪤🕐💡 这类 emoji，看着热闹但很杂，
且不同系统渲染出的样式不一致。已全部移除。

### 2.4 右侧边栏 · 三个标签页

| 标签 | 内容 |
|---|---|
| **大纲** | 大纲文档树 + 当前章节对应的大纲条目高亮；开关：显示伏笔连线（二期） |
| **正文** | 卷-章-节树形目录，显示每章字数与状态色点，支持拖拽排序 |
| **设定集** | 便利贴列表，按分类文件夹分组；搜索框；**拖到稿纸上即变悬浮便利贴** |

### 2.5 左侧边栏 · 功能合集

**两个侧边栏都能拖宽**：把鼠标移到侧边栏靠稿纸那一侧的边上，
出现一条竖线就能拖；双击回到默认宽度。范围 200–640px。
宽度**按面板记，不按左右记** —— 作者把哪个面板拖宽，是因为那个面板内容多，
跟它当时摆在左边还是右边无关，所以左右互换之后宽度跟着面板走。
目录栏默认 250px，功能栏默认 300px（AI 设置那一屏字段多）。

> 作者要求整体以简约为主，**界面上不放图标**，只有文字。
> 下表的顺序就是界面上的顺序。

| 项 | 说明 | 状态 |
|---|---|---|
| **字数统计** | 今日/本周字数、日曲线、年度热力图、连续天数 | ✅ |
| **全文检索** | 搜索框 + 结果列表，可筛选范围（正文/大纲/设定/灵感） | ✅ |
| **设置** | 字体、字号、行距、稿纸宽度、主题、左右互换、字数口径 | ✅ |
| **伏笔** | 未回收清单（默认）/ 全部 / 已回收；点击跳转原文 | ✅ |
| **关联** | 这篇提到了谁 + 谁提到了这篇；坏链单独标出并可一键建卡 | ✅ |
| **版本历史** | 当前文档的版本列表，可对比、可回滚、可打标记 | ✅ |
| **番茄钟** | 计时器 + 今日完成数，无弹窗，顶栏颜色提示 | ✅ |
| **灵感箱** | 手机端记的碎片列表，可「归入」到章节或设定；桌面端也能随手记 | ✅ |
| **AI 助手** | 面板，见 [05](05-功能模块详述.md) 第 9 节 | ✅ |

## 3. 便利贴交互（核心特性）

### 3.1 基本操作

| 操作 | 结果 |
|---|---|
| 从右侧边栏「设定集」标签**拖到稿纸上** | 生成一张悬浮便利贴 |
| 拖动便利贴标题栏 | 移动位置（自动记入 `workspace.json`） |
| 拖动右下角 | 调整大小 |
| 点击便利贴标题 | 折叠/展开（折叠后只剩标题条，节省空间） |
| 双击便利贴正文区 | 在右侧边栏打开完整设定文档编辑 |
| 便利贴右上角 ✕ | 收回（从稿纸移除，不删除文档） |
| 便利贴右上角 📎 | 切换 `scope`：全书常驻 ↔ 仅本章 |

### 3.2 视觉规范

- 半透明背景（默认 92% 不透明度），可在设置里调
- 有轻微投影，视觉上「浮」在稿纸之上
- 不抢焦点：便利贴上的滚动不影响正文滚动
- 便利贴永不阻挡光标 —— 若光标移动到被便利贴遮挡的位置，该便利贴自动降到 40% 不透明度

### 3.3 正文中的 `[[链接]]`

- 鼠标悬停 `[[李四]]` → **弹出便利贴预览**（不需要点击）
- 点击 → 在稿纸上生成一张悬浮便利贴
- `Ctrl+点击` → 在右侧边栏打开完整文档

## 7. 主题与外观（0.4 重做）

写字的人一天里换的不是「白天黑夜」，是**眼睛累到什么程度**。

### 7.1 三套内置主题

| key | 名字 | 什么时候用 |
|---|---|---|
| `light` | 纸白 | 默认。暖白，不用纯白 |
| `eye` | 护眼 | 压过灰的豆沙绿。要的是不刺眼，不是绿 |
| `night` | 夜间 | 近黑（`#0d0d0e`），关了灯只有屏幕亮着时用 |

0.3 有五套，0.4 砍到三套 —— 「纸黄」和「墨灰」跟旁边两档太近，
多出来的两格只是让人多犹豫一次。

**砍掉的档位不能让用户白掉。** `themes.ts` 里留了一张 `RETIRED` 表
（`dark → night`、`sepia → light`），配置里存着老 key 的人打开软件时
落到最近的那一档，而不是被弹回纯白 —— 「我的主题怎么没了」是最糟的升级体验。

### 7.2 主题变量契约

**这是 0.4 的一个决定：不咕鸟有自己的一套主题变量，但凡 Typora 有对应的，
就用 Typora 那个名字。**

为什么不干脆全抄 Typora：它那套名字是为「一整个窗口就是文档」设计的，
没有「热力图」「图表网格线」这种东西，而不咕鸟有。
为什么不干脆全用自己的：那样每一份 Typora 主题都要重写一遍才能用。

所以是**对齐**，不是照抄，也不是另起炉灶。

#### 跟 Typora 同名的（写这些，Typora 主题原样就能改到）

| 变量 | 管什么 |
|---|---|
| `--bg-color` | 页面底色。**稿纸的纸色也从这儿来** |
| `--side-bar-bg-color` | 侧边栏、面板的底色 |
| `--text-color` | 正文字色 |
| `--control-text-color` | 次要文字（按钮、说明、时间戳） |
| `--md-char-color` | 最淡的那层字（标记符号、占位提示） |
| `--primary-color` | 强调色。按钮、链接、选中态都用它 |
| `--item-hover-bg-color` | 鼠标停上去的底色 |
| `--window-border` | 分隔线、描边 |
| `--select-text-bg-color` | 选中文字的底色 |
| `--active-file-bg-color` | 目录树里当前这篇的底色 |
| `--active-file-text-color` | 目录树里当前这篇的字色 |
| `--code-block-bg-color` | 代码块底色 |

后四个在内置主题里是**派生值**（从强调色、抬起底色算出来的），
不单独调色。留着它们不是多余 —— Typora 主题经常单独写这几个，
写了就压过我们的派生值，目录树和选中态跟着一起变。
这正是「对齐命名」要换来的东西。

#### 不咕鸟自己的（Typora 没有对应概念）

| 变量 | 管什么 |
|---|---|
| `--bg-raised` | 浮在底色之上那一层（卡片、弹窗、便利贴） |
| `--danger` | 删除、警告 |
| `--ok` | 完成、达标 |
| `--shadow` / `--shadow-float` | 贴地的阴影 / 浮起来的阴影 |
| `--heat-0` … `--heat-4` | 写作热力图的五档。0 = 没写，4 = 写爆了 |
| `--chart-grid` / `--chart-ink` | 字数图表的网格线 / 线条 |

#### 一个关键的实现细节：写在 `html{}`，不是 `:root{}`

内置主题的那份变量表注在 `<style id="bugu-theme-vars">` 里，选择器是
**`html`**（特指度 0,0,1），而所有主题 CSS 写的都是 `:root`（0,1,0）。

于是**自选主题永远赢**，跟两份样式谁先谁后无关。

这一条是踩出来的：原来用 `:root` 对 `:root`，靠源码顺序决胜，
而 `applyTheme()` 每次都 `appendChild` —— 那会把已有节点**移到末尾**，
于是每改一次设置，内置那份就重新跳到自选主题后面，主题当场失效。
换成靠特指度之后，顺序怎么变都不影响。

### 7.3 稿纸上的行类

Typora 主题里最值钱的规则打向**真正的 Markdown 元素**：`#write h1`、
`#write blockquote`、`#write p`。而不咕鸟的稿纸是编辑器，正文是一堆
`.cm-line` 的 div，里头没有 `<h1>`，也永远不会有。

所以给每一行标上「它是什么」（`renderer/md-line-class.ts`）：

| 类 | 对应 | 认法 |
|---|---|---|
| `.cm-h1` … `.cm-h6` | `h1`…`h6` | 行首 1–6 个 `#` **加空格**（`#标签` 不算） |
| `.cm-quote` | `blockquote` | 行首 `>` |
| `.cm-li` | `li` | 行首 `-` `*` `+` 加空格 |
| `.cm-ol` | 有序列表 | 行首 `1.` `2)` |
| `.cm-code` | `pre` / `.md-fences` | ``` 围栏内，或缩进四格 |
| `.cm-hr` | `hr` | 整行 `---` `***` `___` |
| `.cm-table` | `table` | 行首 `|` 且还有第二根 |
| `.cm-p` | `p` | 剩下的正文 |

两个判定顺序是有意排的：**`hr` 要赢过 `li`**（`---` 不是「减号加空格」），
**围栏内一律算代码**（代码里的 `# 注释` 不是标题）。

**空行不给 `.cm-p`。** 空行在 Typora 里也是 `<p>`，但主题给 `p` 写的段距
落到空行上会翻倍。

**内置外观不用这些类。** 它们纯粹是给主题留的钩子 —— 加上它们那天，
不咕鸟自己长什么样一点没变，这是有意的。

### 7.4 导入一份 Typora 主题时，发生了什么

设置 → 外观 → 自选样式，挑一个 `.css`。三个槽位，双击换，右键改名。

导进来之后按顺序做四件事（`main/theme-css.ts`）：

1. **递归展开 `@import`**，按每个文件**自己**的位置解析相对路径。
   —— 作者那份 `phycat-mint.css` 整份内容都在被 import 的文件里，
   而内联 `<style>` 里的相对路径是相对**页面**算的，不展开就静默全废。
2. **相对 `url()` 绝对化成 `file://`**。`data:` 和 `http(s):` 不动。
3. **选择器桥接**：把 `#write h1` 翻成 `#write .cm-h1`，
   顺手删掉 Typora 内部的结构标记类（`.md-heading`、`.md-end-block`）。
4. **翻出来的追加在原文后面** —— 同权重比顺序，后来者赢。

拿作者那份 phycat 实测：313 条规则里翻出 **62 条**。

#### 三条自我约束

- **只翻 `#write` 底下的。** 裸写的 `h1` 十有八九是它自己的界面（大纲、文件树），
  翻过来只会把稿纸弄花。
- **不动原文，只追加。** 原来那些规则本来就不匹配，留着无害。
- **翻不动就不产出。** 宁可少一条，不要多一条乱命中的。
- **不让主题把整行拽出文档流。** 这是唯一一处我们动主题内容的地方：
  翻出来的规则里，落在行本身上的 `position: absolute|fixed` 和 `float`
  会被摘掉。CodeMirror 靠行的实际位置算光标在哪儿、点到了第几个字 ——
  行一脱流，光标就乱飘，而作者只会觉得「这软件坏了」。
  `relative` / `sticky` 留着（不脱流，而且装饰全靠父级 relative 定位），
  **伪元素上的一概不动**（`::after{position:absolute}` 是正常写法）。

#### 明说做不到的

- **行内元素**（`strong`、`em`、`a`、行内 `code`）翻不了 ——
  它们在一行**内部**，而我们只能给整行贴类。
- **Typora 自己的界面**（侧栏、标签页、菜单）那 188 条规则，
  没救也不该救 —— 那是别人的界面。
- 子代组合器会被放宽成后代（`#write > h1` → `#write .cm-h1`）：
  我们中间还隔着 `.cm-editor` / `.cm-scroller` / `.cm-content` 三层，
  留着 `>` 等于没翻。

#### 装完要给回执

「装上了但看不出变化」是这功能最难自查的一种坏法 ——
作者那边只有「没变」两个字。所以装完当场回报三件事：
**装进去多少 KB**、**改到了几个颜色变量**、**翻译了几条排版规则**。

颜色和排版是两条独立的路，**必须分开说** —— 合成一句话，作者就分不清
是哪条断了。

上限 2MB，拦的是「手滑选了个 200MB 的文件」。

### 7.5 自定义主题栏位（会长的一排）

导进来的 Typora 主题、自己调的那几套，**共用同一排格子**。

一开始只有一个空位。用掉它（导一份 CSS，或者存一套自己调的）之后，
**末尾立刻又长一个空位**出来 —— 于是可以一直加，直到九个。

```
预设   [纸白] [护眼] [夜间]
自定义 [phycat mint] [夜航船] [＋]
                              ↑ 用掉它，后面又长一个
```

- **空位就是「加」这个按钮。** 界面上不需要另外放一个「新建」，
  也不需要写「最多几个」—— 满九个时空位自己消失，那比一句话管用。
- **一格可以是两种东西**：一份 CSS 文件，或者一套自己调的（存的是值）。
  存的东西不一样，但**在界面上完全一样**：一个色块、双击、右键改名、
  叉掉删除。作者不需要记得哪格是哪种。
- **双击**：文件主题 → 换一份 CSS；自制主题 → 打开调色器接着调那一格。
- **右键**改名。
- **满九个时不许挤掉最老的那一份** —— 那是别人调了半天的配色。
  想加就先删一个，界面直说。
- **删的是整格，不是把它清空。** 清空会在中间留个洞，
  而那个洞看起来跟末尾的空位一模一样，点下去却是另一回事。
  删掉正在用的那格 → 回预设；删掉它前面的 → 序号往前挪，不然会悄悄换主题。
- 提示只写**怎么操作**：「双击自定义主题更换 CSS 文件，右键改名。」
  原来这行在没选自定义主题时会去介绍预设（「暖白，像一张纸……」）——
  预设那三个色块自己就说清楚了，而这两个动作没地方能看出来，必须写。
- 删除确认说的是后果：「删除后再次使用需重新导入。」

九是上限：再多一排就摆不下、也认不出来了。

规矩全在 `shared/theme-slots.ts`，界面和主进程用**同一份** ——
各写一份的话，迟早有一边少挤一个空位。

历次形状变化都有迁移（`config-migrate.ts`）：
`themeCss` 一个字符串 → 三个字符串 → 三个对象 → 现在这排。
接不上的后果不是报错，是「我的主题怎么没了」。

### 7.6 调色器（自己调一套）

导别人的主题这条路走到头之后加的。**它才是推荐路径。**

为什么：上面 7.4 已经把能做的都做了，而剩下做不到的是**结构性**的 ——
一份 Typora 主题里一多半规则打向它自己的界面，我们没有那些东西；
还有一整类主题（phycat 那种）根本不定义纸色，装上之后纸还是白的，
而作者只会看到「怎么没变」，然后开始怀疑是不是漏了文件。

所以换个方向：**把 7.2 那份变量契约变成一个能点的东西。**
调出来的一定完整、一定生效、一定能导出给别人。

#### 长什么样

设置 → 外观 → 「自己调一套」。左边一列表选调哪一项，右边调那一项：

```
┌────────────┬──────────────────────────┐
│ 底         │  页面底色                 │
│ ■ 页面底色 │  稿纸的纸色也是它          │
│ ■ 侧边栏   │  --bg-color  [Typora 同名] │
│ ■ 浮起的层 │                           │
│ ■ 线       │  ┌────────────────────┐   │
│ 字         │  │      色盘          │   │
│ ■ 正文     │  └────────────────────┘   │
│ ■ 次要文字 │  色号 [#fbfaf7    ]        │
│ …          │  R[251] G[250] B[247]     │
└────────────┴──────────────────────────┘
 [用这套] [导出 CSS] [回到起点]
```

**一列表加一编辑区，不是二十几个色块并排。** 并排是一面墙，
而且每个色块旁边塞不下「它管什么」那句话 —— 而那句话正是能不能调对的关键。
这也是唯一能同时放下**色盘 + 色号 + RGB** 三种输入的排法。

#### 几个刻意的决定

- **起点是当前那个预设，不是空白。** 从零调一套没人受得了 ——
  二十几个颜色，第一个就得凭空想。永远是「拿一套改」。
- **改一下当场生效。** 调颜色没法靠想，「先调完再看效果」
  等于让人闭着眼睛调二十几次。
- **预览不写配置。** 拖色盘一秒能出几十个值，每个都存盘会卡到拖不动。
  存盘是按「用这套」那一下的事。
- **收起时恢复成配置里真正生效的那份。** 不恢复的话，调了半天没按
  「用这套」就关掉，屏幕上还留着那套颜色，重启却没了 ——
  「看着是这样、其实不是」比调不动更让人摸不着头脑。
- **草稿存的是值，不是文件。** 存成文件再读回来就得反过来解析 CSS，
  那一步只要有一处解错，配色就丢了。导出成 `.css` 是**另一件事**。
- **三档互斥**：三个预设、三个文件槽位、自己调的那套 ——
  用哪一档，另外两档让位。同一时刻页面上只有一份自选样式，
  不会出现两份 CSS 互相压。

#### 字体也算主题的一部分

调色器里能选正文字体，导出的 CSS 带着它，别人导入时稿纸的字也跟着变。

为此把 `--font-body` 从**行内样式**挪进了样式表（`themes.ts` 的
`applyFontVar`）—— 行内样式压过一切，留在那儿的话主题里写了也没用。

**字号、行距、页宽仍然是行内的**，这是有意的分界：
字体是「这套主题长什么样」，字号行距是「这台机器上这双眼睛要多大」。
后者不该被一份主题改掉。

#### 导出

「导出 CSS」写出的文件跟 7.4 认得的格式完全一致 ——
也就是说**导出的这份，用「自选样式」能再导回来**，也能直接发给别人。
文件带 `/* Theme Name: … */` 和分组注释，是给人看、给人改的。

调好之后按「存到自定义栏」，它就占一格（见 7.5），和导进来的主题摆在一起 ——
**能存好几套，点一下就换**。在那之前自己调的只有一份，调第二套就把第一套顶掉了。

仓库里另有一份 `主题模板/不咕鸟示例主题.css`，是同样格式的手写模板 ——
不想用调色器、想直接写 CSS 的话照着改就行。

### 手动保存的小回执（0.3 加）

按 Ctrl+S 之后右上角浮一下：**距上次手动保存新增了多少字**，外加本篇总字数。

- **只在手动保存时弹。** 自动保存三秒一次，弹一次就是每三秒糊一次脸。
- 基线按**文档**记，不是一个全局数 —— 作者在两篇之间来回切时，
  全局基线算出来的「新增」是两篇字数之差，那是个没有意义的数。
- 打开一篇时先记一笔当时的字数，所以第一次按 Ctrl+S 报的是
  「打开之后写了多少」，那正好也是他想问的。
- `position: fixed` + `pointer-events: none`：它一进文档流就会把稿纸往下顶一行，
  正在写的那行会跳，比不弹还糟；而它正压在顶栏边上，能点的话就成了障碍物。

### 启动时的那**一个**弹窗（0.3）

一屏说完三件事，底下两个按钮：

```
        7
    连胜 7 天
   最长纪录 21 天

 今天的底线是 1000 字，已经写了 320。

 ┌───────────────────────────┐
 │ 上次写到                    │
 │ 《不咕鸟传》· 第三章 雨夜  第 42 行 │
 └───────────────────────────┘

     [进入书架]  [回到上次]
```

**连胜和「回到上次」不拆成两个弹窗。** 初版是拆的：先弹连胜，关掉，
再弹一个问要不要回去 —— 作者的反应是「应该将二者合为一个」，他说得对。
这两件事在他脑子里本来就是同一件：**打开软件的那一秒，他要知道
「我现在什么状态、该回哪儿去」**。拆成两步之后，第一个弹窗就成了一道
必须先点掉的门，而门后面才是他真正要做的选择。

- **先把「上次在哪儿」算完再弹**，不是先弹出来再补上去 ——
  后者会让第二个按钮凭空冒出来一个，正好在他要点的位置上。
- 回车 = 回到上次（没地方可回时 = 进书架）。多数时候他就是想接着写，
  那一下不该要他动鼠标。Esc = 进书架。
- 上次那一篇的**篇名和行号都要说**。只说书名的话，回去还得自己找光标在哪儿，
  而「上次写到哪一行」正是他想回去的那个点。
- **一次启动只问一次，而且只在「还没进过任何一本书」的时候问。**
  三个条件缺一不可：用的是**启动那一刻的快照**（不是活的 `lastPlace` ——
  那一项在作者写字的过程中一直在被更新）、这次启动没进过书、没问过。
  少任何一个都会变成「写完一本退回书架，忽然被问要不要回上一本」——
  而他明明是打算开另一本（作者报过这个）。
- 时机跟连胜问候接上：问候看完了才问，一上来两个弹窗叠着很吓人。
- 位置存在**本机配置**（`lastPlace`）里，不进作品目录 ——
  这是「这台电脑上的我」停在哪儿，跟着同步跑到另一台电脑上只会打架。
- 那本书被删了、改了名就当没这回事，**不弹一个点了会报错的按钮**。

可配置项（放设置页）：
- 主题、自选样式
- 正文字体、字号、行距、段间距
- 稿纸最大宽度（默认 720px，写作时不要让行太长）
- 便利贴不透明度
- 是否显示实时字数

## 稿纸上的右键菜单（已实现）

> **菜单会躲开选中的那一段（0.3 修）。**
>
> 稿纸上的菜单有十几条，从光标处往下开正好盖住刚选中的字 ——
> 右键想复制的时候，连「我选对了没有」都核对不了（作者报过这个）。
>
> 现在带上选区的位置：压住了就挪。**先往右、再往下**，往上翻是最后一招 ——
> 往右挪最不打断视线（选中那段还在原地，菜单摆它旁边），
> 而往上会盖住上面几行，那多半也是刚写的东西。
> 四个方向都放不下（选区大到占满屏幕）就维持原样，挪到更糟的地方还不如不挪。
>
> 摆放算式是纯函数 `placeMenu()`，12 个测试钉着 ——
> 它一坏就是「菜单缺半截」或者「又盖回去了」，两种都只能靠人眼盯。


**Electron 默认什么右键菜单都没有** —— 不自己接 `contextmenu` 事件，
作者在稿纸上右键就是一片死寂。这是作者试用时报的问题。

| 组 | 项 |
|---|---|
| 编辑 | 剪切 / 复制 / 粘贴 / 全选 |
| 插入 | 便利贴浮出（`@…@`）、整行浮出（行首 `@`）、双链 `[[ ]]`、标为伏笔 |
| 排版 | 二级标题 `##`、分隔线 `——` |
| 剧本 | 场景标题 `#`、动作 `（）`、表演提示 |
| 游戏剧本 | 选项 `- 文字 -> 目标`、跳转 `-> 节点`、条件 `{}`、变量 `$`、条件块 `$若 … $结束` |

两个刻意的决定：

- **剪切/复制/粘贴走主进程的 `webContents` 原生命令**，
  不用渲染进程里的 `execCommand` —— 后者在 CodeMirror 这类自己管选区的
  编辑器里时灵时不灵，而 Chromium 的原生编辑命令作用在当前焦点上，必然对。
- **后两组按作品类型给**：剧本书给剧本那组，游戏书给两组都给，
  小说书一组都不给 —— 写长篇小说的人不需要在菜单里天天看见「跳转」。
  没标类型的老书退回原来的判法（正文里有没有 `->`），行为一个字没变。

有选中时，「插入」会把选中的那一段**包起来**而不是替换掉；
没选中就在光标处插入并把光标停在中间，接着打字就行。

## 书架左侧的用户栏（已实现）

宽 190px，刻意做窄 —— 作者原话：「应该不需要占据太多空间。」

| 显示 | 说明 |
|---|---|
| 昵称 | 点一下就能改。存在 `_计划.yaml` 里，跟着同步走 |
| 一起写了 N 天 | **不叫「注册天数」—— 这软件没有账号。** 从第一条码字记录那天算起，另外标出其中几天真的动过笔 |
| 今天 | `1,800 / 3,000` + 一条细进度条 |
| 连胜 | 大字 + 7/30/100/365 天的小徽章 |
| 本周 | `5 / 7 天达标`。**请假日不算进分母** —— 出差三天还显示 4/7 会让人觉得自己在偷懒，而他并没有 |
| 设置 | 底部一个按钮，开总设置 |

**写作页只补一个「连胜 N 日」**，摆在原有的「今日 X 字 · 还差 Y」旁边。
作者原话：「写作页本来就有当前码字和今日目标了，在旁边补上一个连胜XXX日即可。」
稿纸旁边不该再摆更多东西分心。

### 关于「鼓励」，几条自己给自己定的规矩

作者提到多邻国的连胜机制。那套东西有效，但很容易做成**让人焦虑而不是让人写**：

1. **连胜要显眼，断了要平静。** 多邻国断了会弹一堆挽留，那是在卖付费补签。
   这儿断了就是断了，安静地重新计数，旁边留一行「上次连了 N 天」当参照 ——
   那是「上次到过哪儿」，不是「你搞砸了」。
2. **不发明第二套「护级卡」。** 补签额度已经有了，就用它。
   而且面板上会写明这段连续里有几天是补签的、几天是请假撑着的 ——
   **撑出来的天数要让作者知道，不然这个数字就是在骗自己。**
3. **徽章只在 7 / 30 / 100 / 365 天给。** 天天弹恭喜会麻木。

### 启动时的连胜问候

**一次启动只弹一次** —— 不是每次回书架、不是每次换书。弹第二次它就从鼓励变成打扰了。

弹窗里：连胜天数（断了就是安静的 0 + 「上次连了 N 天」）、
今天的底线是多少、已经写了多少。一个「开始写」按钮。

首次上手引导还没看完时不弹 —— 一上来两个弹窗叠着很吓人。

## 总设置（已实现）

作者定的规矩：**不常改的进总设置，常改的或跟写作页关系大的留在侧边栏。**

| 位置 | 放什么 |
|---|---|
| **总设置**（书架左下角「设置」） | 关于你（昵称、写了多少天、连胜）／码字目标／AI（服务商、端点、Key、单价、代理）／作品库目录 |
| **写作页右侧「设置」** | 字号、行距、字体、稿纸宽度、主题、左右互换、字数口径 |

字号这类要一边写一边调的东西塞进浮层，等于每次调字号都要开关一次窗。
总设置的侧栏底部专门写了一句话指路，省得作者满界面找。

总设置里的「码字目标」和「AI」**直接复用**已有的那两块编辑器组件，
不为了「有个总设置页」重写一遍。

## 12. 图文说明（新手教程，已实现）

按 F1 或菜单里的「帮助」打开，六个页签：

| 页签 | 内容 |
|---|---|
| 先看这些 | 六句话的上手指引（原来就有的） |
| **书架页** | 用户栏、右键作品、新建时选类型、换目录 |
| **小说稿纸** | 两边的栏怎么划出来、自动保存、`@` 便利贴、右键插入 |
| **剧本稿纸** | 场景 `#`、`角色名：台词`、**先去建人物卡**、剧本面板、排版只改显示 |
| **游戏稿纸** | 节点、选项跳转、变量条件、体检、导出引擎 |
| 快捷键 | 键位表 |

### 每种稿纸各一页，不合成一份

小说、剧本、游戏剧本在这软件里长得不一样 —— 面板不一样、右键菜单不一样、
正文该怎么写更不一样。一份总说明要么把三种混着说，要么只说小说那种，
另外两种的人第一次打开就是懵的。

### 只弹当下这一页，而且各弹一次

第一次进书架弹「书架页」，第一次打开一本剧本弹「剧本稿纸」。
**看过没看过按页面记**（`seenTours`）：只写小说的人不该被弹游戏剧本那一页，
而他哪天真开了本剧本，那一页还得弹。

弹窗有先后：上手指引 → 连胜问候 → 图文说明。
后面的会等前面的关掉才上来 —— 一上来三个弹窗叠着谁都受不了。

### 图是画的，不是截图

内联 SVG，配色走主题变量。截图会随着界面改而过期，而且深色模式下是白的；
示意图跟着主题走，改了界面也不至于对不上。

## 13. 功能栏里放什么、不放什么（2026-08-27 按作者反馈重排）

功能栏（划出来的那一条）现在是这些：

```
字数统计 · 全文检索 · 设置 · 伏笔 · 关联 · 版本历史
里程碑 · 番茄钟 · 灵感箱 · [剧本模式] · [游戏剧本] · 回收站 · AI 助手
```

### 剧本模式 / 游戏剧本按作品类型给

| 作品类型 | 多出来的面板 |
|---|---|
| 小说 | 无 |
| 剧本 | 剧本模式 |
| 游戏剧本 | 剧本模式 + 游戏剧本 |

写哪种东西是**这本书的属性**，在书架上定（右键那本书）。
边写边在功能栏里换模式，等于让作者以为「格式是可以随手切的」，而它不是。
小说书里根本不该出现「游戏剧本」这一条。

> 游戏剧本也给「剧本模式」：它本来就是剧本，
> 「谁的戏多」「谁好久没出声了」照样用得上。

在书架上改了类型再进来，原先选中的面板要是没了，自动退回「字数统计」。

### 码字计划不在这儿，里程碑在

- **码字计划**整块搬去书架的总设置。目标是「人」的属性、不分在写哪本书，
  判定用的是全部作品当日字数的合计 —— 它不该住在某一本书的侧边栏上。
- **里程碑**留下。那是**按书**的（「这一卷什么时候写完」），
  跟正在写的这本关系极大。

### 回收站留在这儿

它本来就是**按书**的（`listTrash(bookPath)`）——
在这本书里删掉的章节，就该在这本书里捞。

## 14. 书架上的灵感箱与置顶（已实现）

### 灵感箱是书架上的第一张卡

**每个分类标签下都在**，永远排第一。点一下弹一个框，写完就走。

想到一个点子的时候往往还不知道它属于哪本书，甚至不知道要不要为它开一本书 ——
逼着人先挑一本，那个点子多半就飞了。所以它落在**全库共用**的
`_灵感箱` 里，不属于任何一本书；回头在写作页的「灵感箱」面板里
再把它归进某一章。

弹框里刻意只有一个多行输入框：没有标题、没有分类、没有「属于哪本书」。
灵感是几秒钟的东西，多问一个问题它就飞了。标题由第一行凑。
Ctrl+Enter 直接存下，手不用离开键盘。

卡片右上角是待归的条数。

### 置顶

右键一本书 →「置顶」。置顶的排在书架最前面（灵感箱之后），
封面右上角有个图钉。

存在书自己的 `book.yaml` 里（`pinned: true`），不是一份全局清单 ——
那样换台电脑、或者把某本书单独拷走，置顶都跟着走，
也不会留下一条指向不存在的书的记录。

**都置顶时仍按书名排。** 置顶是「常写的那几本别翻」，
不是又一套要手工维护的顺序。

## 15. 书架右键菜单（2026-08-27 收拢）

```
打开
─────────────
置顶 / 取消置顶
重命名…
─────────────
更改书籍格式（剧本）  ›   小说 / 剧本 / 游戏剧本
更改书籍状态（连载中）›   连载中 / 完结 / 坑啦！哈哈
─────────────
更换封面… / 移除封面
─────────────
在资源管理器中显示
─────────────
删除作品…
```

原来那六条互斥选项是**平铺**在一级菜单上的（「按『小说』排版」「标为『连载中』」
各三条），一屏十一条，把「打开」「重命名」这些真正常用的挤到得扫一遍才找得到。
收成两个下级菜单之后一级只剩八条。

父项上带着**当前是哪个**（`更改书籍格式（剧本）`），
不用展开就知道这本书现在是什么。子菜单里当前那一项打勾并置灰。

### 下级菜单的两个实现要点

- **画在父项里面，不用 portal。** 关菜单那个判断是
  `ref.current.contains(e.target)` —— portal 出去就不算「点在菜单里面」，
  点子菜单会把整个菜单关掉。
- **悬停展开，收起有 220ms 延迟。** 鼠标从父项斜着挪到子菜单时会短暂地
  两边都不在，不留这点余量的话子菜单会在半路消失。
  父项本身也能点（切换展开）—— 触屏和键盘上进得去。

> ⚠️ React 的 `onMouseEnter` 走的是 `mouseover` 委托，
> 合成一个 `mouseenter` 事件是叫不动它的。验证时得发真的输入事件。
